# 云端自动化平台生产化修复实施方案 V2

> 编写日期：2026-08-22  
> 适用目录：`cloud-platform/`  
> 文档性质：实现任务书、验收标准、代码审查基线  
> 实施对象：后续负责修改代码的 Agent

## 1. 文档目标

当前代码可以编译，工作区 135 个测试也能够通过，但尚未形成可运行的真实生产闭环。现有测试主要验证领域函数和局部逻辑，没有验证 Master、Worker、gRPC、浏览器、Webshare 和 NAS 组合后的行为。

本轮修复的目标不是继续增加“看起来完整”的模块，而是打通并验证以下真实链路：

1. Worker 注册并等待管理员审核；
2. 管理员为不同 Worker 设置槽位数；
3. Worker 通过安全的 gRPC 长连接上线；
4. Master 为每个空闲槽位锁定账号和 Webshare 代理；
5. 同一会话、同一本书从开始到结束始终使用同一个出口 IP；
6. Worker 使用真实站点地址启动浏览器并下载正确的图书；
7. 文件通过局域网写入同一台 NAS；
8. Worker 向 Master 上报可验证的结果；
9. Master 幂等地完成任务、额度、文件和批次记账；
10. 断网、重连、取消和进程重启时不产生重复下载或错误完成。

任何一项没有通过真实端到端验证，都不能把项目标记为“生产完成”。

## 2. 不可变业务约束

后续实现必须遵守以下约束，不得通过改需求绕过缺陷。

### 2.1 部署结构

- Master 部署在云服务器；
- Worker 是家里和办公室的异地电脑；
- Worker 可能运行 Windows、macOS 或 Linux；
- Worker 主动连接 Master，云端不得反向访问家庭局域网；
- 第一阶段约 5 台物理 Worker；
- “Worker 数”指物理电脑数量；
- 每台 Worker 可以配置不同槽位数量；
- 槽位代表同一台电脑允许同时运行的浏览器执行单元。

### 2.2 NAS

- 所有 Worker 与同一台 NAS 位于同一个局域网；
- 文件由 Worker 通过局域网直接写入 NAS；
- 每台 Worker 可以配置自己的 NAS 挂载路径；
- 云端 Master 不承担图书文件中转；
- 同一本书、同一种格式全局只保存一份有效文件。

### 2.3 代理

- 继续使用 Webshare；
- 每个下载会话固定绑定一个 Webshare 代理；
- 一本书从登录、搜索、点击下载到文件完成必须使用同一个出口 IP；
- 禁止在一本书下载过程中自动轮换代理；
- 代理失败时结束当前会话，重新分配新会话和新代理。

### 2.4 管理与数据表达

- 管理员可以审核、暂停、恢复 Worker；
- 管理员可以设置各 Worker 的槽位上限；
- 管理员可以设置批次优先级；
- 业务状态值必须使用中文，例如“待审核”“在线”“已注册”“执行中”“已完成”；
- `pdf`、`epub`、`http`、`socks5`、UUID、IP、操作系统名等技术标识不强制中文化。

## 3. 当前阻断问题

### 3.1 P0：Worker 业务消息没有进入 gRPC 上行流

当前 `run_agent_loop` 创建了供槽位使用的 `out_tx/out_rx_bridge`，但 `out_rx_bridge` 从未被消费。`connect_and_serve` 又创建了独立的 `stream_tx`。

因此以下消息不会到达 Master：

- `SessionReady`；
- `NextTaskRequest`；
- `TaskAccepted`；
- `TaskProgress`；
- `TaskResult`；
- `SessionClosed`。

后果是 Master 可以下发 `CreateSession`，但会话永远无法进入完整任务闭环。

### 3.2 P0：任务阶段版本协议不完整

Master 领取任务时会增加 `book_tasks.stage_version`，但 `AssignTask` 没有携带该字段。Worker 把执行阶段写死为 `1`，把结果阶段写死为 `2`。

Master 提交结果时要求上报版本与数据库当前版本完全一致，因此正常成功结果也会被判为过期事件，仅留档而不完成任务。

### 3.3 P0：真实模式使用占位站点

Worker 创建 `SessionSpec` 时把 `site_base` 写死为 `https://example.invalid`。Master 已经在 `NodeConfig` 中下发真实地址，但 Worker 只记录日志，没有保存和应用动态配置。

### 3.4 P0：浏览器下载目录与任务检测目录不一致

浏览器会话指向公共 `staging` 目录，任务却扫描 `staging/task_<task_id>`。即使浏览器完成下载，任务也可能永远找不到文件并超时。

### 3.5 P1：管理员槽位配置未应用到 Worker

Worker 在启动时按照本地 `requested_slots` 固定创建槽位。云端下发的 `NodeConfig.max_slots` 不会扩容、缩容或停用本地槽位。

### 3.6 P1：取消和结束命令无法打断任务

槽位在等待真实下载期间不再读取命令通道。`CancelTask` 没有在会话循环中处理，任务完成前无法取消。`EndSession.finish_current_task=false` 也无法立即停止。

### 3.7 P1：审核后节点可能继续显示离线

节点审核时状态被设置为“离线”。如果 Worker 在审核前已经连接并发送过 `NodeOnline`，审核后只继续发送心跳，不会再次触发上线状态迁移。

### 3.8 P1：mTLS 注册和连接未落地

Worker 注册时没有生成私钥和 CSR；注册响应中的证书、CA 没有保存；建立 gRPC 连接时也没有读取客户端证书、私钥和 CA 配置。

### 3.9 P1：NAS 核验标准过松

Master 对“待确认”文件的核验只检查文件大小，未严格比较路径、文件名、格式、SHA-256 和期望大小。Worker 的可写状态、剩余空间和延迟还存在固定占位值。

### 3.10 P1：真实自动化没有验证书籍匹配

当前真实引擎在搜索后可能直接点击第一个结果，没有严格校验书名、作者、出版社和 ISBN；下载后也没有调用文件格式与目标名称验证逻辑。

### 3.11 P1：全局图书合并和批次取消语义不完整

- 图书合并只修改部分批次关联，没有完整迁移任务和文件；
- 目标关联已存在时，源关联可能被保留；
- 源图书的任务和文件仍可能存在；
- 批次取消只保护其他“执行中”批次，没有保护“待开始”和“已暂停”批次的共享任务。

### 3.12 P2：Webshare 同步不完整

- API 返回的 `valid` 字段没有参与状态判断；
- 已从 Webshare 消失的代理不会自动停用；
- 同步后没有形成可靠的有效代理集合快照。

## 4. 修复后的目标架构

Worker 进程内应形成三个长期组件：

```text
WorkerRuntime
├── ConfigState       Master 动态配置的当前快照
├── LinkRuntime       gRPC 连接、重连、心跳、上行发送、下行分发
├── LocalStore        SQLite Outbox 与执行现场
└── SlotManager
    ├── SlotRuntime[0]
    ├── SlotRuntime[1]
    └── ...
```

核心要求：

- `SlotManager` 生命周期长于单次 gRPC 连接；
- 所有槽位只有一个统一的上行出口；
- gRPC 断线时，可靠业务事件先写入 Outbox；
- 重连后 Outbox 和实时消息经同一个发送器进入新链路；
- 动态配置由 `ConfigState` 保存，槽位在新建会话时读取最新快照；
- 当前任务的取消令牌独立于命令通道，可在浏览器执行期间立即触发。

## 5. 第一阶段：修复统一消息链路

### 5.1 改造目标

删除“创建了接收端但不消费”的桥接方式。推荐使用一个长期的逻辑上行总线：

```rust
struct OutboundEventBus {
    tx: mpsc::Sender<WorkerMessage>,
}
```

`SlotManager`、心跳模块和 NAS 核验模块都写入同一个总线。连接管理器是唯一消费者，并负责将消息发送到当前 gRPC 流。

### 5.2 连接期行为

连接成功后必须按顺序执行：

1. 向当前 gRPC 流发送 `NodeOnline`；
2. 补发 Outbox 中未确认事件；
3. 启动实时上行消息转发；
4. 启动心跳；
5. 接收并分发 Master 命令。

断线后：

- 不销毁 `SlotManager`；
- 不销毁当前浏览器任务；
- 停止向旧的 `stream_tx` 发送；
- 可靠事件继续写入 SQLite；
- 进度类事件允许丢弃或合并；
- 重连后先完成对账再申请新会话。

### 5.3 可靠事件范围

以下事件必须先写 Outbox，再进入实时发送队列：

- `SessionReady`；
- `TaskAccepted`；
- `TaskResult`；
- `SessionClosed`；
- `NasCheckResult`；
- `ProxyCheckResult`。

以下事件允许不进入 Outbox：

- `Heartbeat`；
- `SlotStatusReport`；
- 可合并的 `TaskProgress`；
- 周期性的 `SessionRequest` 和 `NextTaskRequest`。

### 5.4 验收标准

- 启动一个模拟 Worker，Master 能依次收到 `NodeOnline → SessionRequest → SessionReady → NextTaskRequest → TaskAccepted → TaskResult → SessionClosed`；
- 人为断开 gRPC 后产生的 `TaskResult` 能在重连后补报；
- 收到 `EventAck.accepted=true` 后对应 Outbox 记录被删除；
- 同一 `event_id` 重放两次，Master 只应用一次。

## 6. 第二阶段：统一阶段版本语义

### 6.1 协议修改

在 `AssignTask` 中新增：

```proto
uint32 stage_version = 12;
```

生成代码后，Master 的 `assign_task_message` 必须发送领取事务返回的真实版本。

### 6.2 版本规则

`stage_version` 表示“本次任务租约世代”，不表示界面上的搜索、下载、入库步骤。

同一次 `AssignTask` 生命周期内，以下消息必须使用完全相同的版本：

- `ActiveExecution`；
- `TaskProgress`；
- `TaskResult`。

Worker 不得自行增加 `stage_version`。只有 Master 在重新领取、回收、人工重试或其他会使旧执行失效的操作中增加它。

“搜索中”“下载中”“等待入库”等使用 `stage` 字符串表达，不能通过增加 `stage_version` 表达。

### 6.3 Worker 执行现场

接收 `AssignTask` 后保存：

```text
task_id
execution_id
session_id
attempt
stage_version
accepted_at
```

心跳、进度和最终结果均从这一份现场读取，不得写死数字。

### 6.4 验收标准

- 第一次成功结果能够将任务置为“已完成”；
- 第二次重试的版本大于第一次；
- 第一次执行的迟到结果不能覆盖第二次执行；
- 当前执行的心跳可以持续续租；
- 迟到进度不能使已完成任务发生状态倒退。

## 7. 第三阶段：动态配置和管理员槽位控制

### 7.1 ConfigState

Worker 增加线程安全的动态配置快照，至少包含：

- `config_version`；
- `node_name`；
- `node_status`；
- `max_slots`；
- `upload_concurrency`；
- `heartbeat_interval_secs`；
- `session_renew_secs`；
- `progress_min_interval_secs`；
- `progress_min_bytes`；
- `max_session_duration_secs`；
- `stall_timeout_secs`；
- `nas_relative_root`；
- `minimum_free_gb`；
- `site_base`；
- `download_format`；
- `diagnostics_enabled`。

收到 `NodeConfig` 后必须校验并原子替换快照，然后在心跳中上报 `applied_config_version`。

### 7.2 槽位扩缩容

- 扩容：创建新的长期槽位协程；
- 缩容：空闲的超限槽位立即置为“已停用”；
- 正在执行的超限槽位完成当前任务和会话后再停用；
- 禁止强制杀死正在写 NAS 的任务；
- 本地 `requested_slots` 仅表示注册时请求值和本机安全上限；
- 实际运行数量不得超过 Master 下发的 `max_slots`。

### 7.3 节点审核状态

审核节点时：

- 如果 `connected=true` 且最近心跳有效，应直接置为“在线”或“存储异常”；
- 如果没有有效连接，置为“离线”；
- Worker 不应为了让审核生效而手工重启。

心跳处理时：

- “待审核”“已禁用”“维护中”“已暂停”不能被心跳自动覆盖；
- 已审核且正常连接的“离线”节点可恢复为“在线”；
- NAS 不健康时改为“存储异常”；
- NAS 恢复后可回到“在线”。

### 7.4 暂停与恢复

Worker 必须处理 `PauseNode` 和 `ResumeNode`：

- `finish_current_task=true`：当前任务完成后结束会话，不再申请下一本；
- `finish_current_task=false`：触发当前任务取消，然后结束会话；
- 恢复后仅恢复可用槽位，不自动复活已结束会话。

### 7.5 验收标准

- 管理员把某 Worker 从 5 个槽位改为 2 个，本地最终仅保留 2 个可运行槽位；
- 再从 2 个改为 4 个，新槽位可以领取会话；
- 审核已经在线连接的 Worker 后无需重启即可工作；
- 暂停后不再领取新任务；
- 动态站点地址确实进入新建浏览器会话。

## 8. 第四阶段：真实浏览器下载闭环

### 8.1 会话配置

真实 `SessionSpec` 必须使用动态配置：

- `site_base` 来自 `ConfigState.site_base`；
- `download_format` 来自任务或动态配置；
- `headless` 应由配置控制；
- 浏览器路径允许本地显式设置；
- 代理端点来自当前会话的固定本地转发端口。

启动前拒绝以下配置：

- 空站点地址；
- `example.invalid`；
- 非 HTTP/HTTPS 地址；
- 真实模式下没有账号；
- 图书下载会话没有代理；
- NAS 不可写。

### 8.2 任务级下载目录

每个任务使用独立目录：

```text
data/staging/task_<task_id>/
```

在点击下载前设置当前浏览器页面的下载目录为该目录。禁止浏览器写公共 staging 根目录后再靠“最新文件”猜测任务归属。

任务开始前：

- 创建空的任务目录；
- 清理该任务上一次遗留的 `.crdownload`、`.tmp` 等临时文件；
- 不得删除其他任务目录。

### 8.3 搜索结果匹配

不得直接点击第一个搜索结果。按以下顺序匹配：

1. 标准化 ISBN 完全一致；
2. 标准化书名完全一致，并结合作者；
3. 标准化书名、作者、出版社综合匹配；
4. 只有书名且存在多个候选时返回“待确认”或“未找到”，不得猜测。

匹配过程必须记录：

- 搜索词；
- 候选数量；
- 选中候选的书名、作者、ISBN；
- 匹配依据。

### 8.4 登录判断

填写账号密码并点击提交后，必须确认至少一个成功条件：

- 出现已登录用户元素；
- URL 离开登录页；
- 用户菜单或额度元素出现。

找不到输入框、提交失败或仍停留在登录页时不能返回成功。

### 8.5 下载完成判断

必须同时满足：

- 临时扩展名已经消失；
- 文件大小在稳定窗口内不再变化；
- 文件大于配置的最小字节数；
- 扩展名与任务格式一致；
- PDF/EPUB 文件签名正确；
- 文件属于当前任务目录；
- 下载耗时没有超过会话和任务限制。

### 8.6 验收标准

- 使用真实测试账号完成至少一本测试书下载；
- 浏览器访问的是配置中的真实地址；
- 下载文件只出现在当前任务目录；
- 搜索结果顺序变化时仍能选中正确书籍；
- 登录失败、未找到、代理失败、下载超时能够被正确分类。

## 9. 第五阶段：固定 Webshare 代理

### 9.1 会话固定原则

一个 `CreateSession` 绑定：

```text
session_id → proxy_id → 上游 host:port → 本地固定端口
```

该映射在会话结束前不能改变。任务失败时不能在原会话内部偷偷切换代理。

### 9.2 转发实现

可以选择以下方案之一：

1. 使用成熟的本地代理程序并由 Worker 管理其生命周期；
2. 完善现有 Rust 转发器。

若保留自研转发器，必须处理：

- 完整读取 HTTP 请求头，不能假设 4096 字节一次读完；
- `CONNECT`；
- 普通 HTTP 绝对 URI 请求；
- 长连接中的后续 HTTP 请求；
- 每个需要认证的请求都注入 `Proxy-Authorization`；
- 上游返回 `407` 时明确报代理认证失败；
- 连接超时、DNS 失败和隧道断开；
- `http`、`https`、`socks5` 方案分流；
- 停止会话时关闭监听器和存量连接。

### 9.3 出口 IP 验证

会话启动后、登录前，通过当前本地代理请求可信的 IP 查询服务，并上报：

- `proxy_id`；
- `exit_ip`；
- 延迟；
- 是否可达。

`SessionReady.exit_ip` 不能保持空字符串。会话执行期间可在关键阶段复查出口 IP；如果发生变化，当前任务应转为“待确认”或失败并结束会话。

### 9.4 Webshare 同步

一次完整同步应：

1. 拉取所有分页；
2. 记录本次出现的代理 ID；
3. `valid=false` 的代理标记为“已停用”或“异常”；
4. 上次存在、本次完整快照中消失的代理标记为“已停用”；
5. 正在被会话占用的失效代理不立即重分配，但会话结束后不能恢复可用；
6. 只有 `valid=true` 且健康检查通过的代理可以分配。

### 9.5 验收标准

- 同一本书下载前后出口 IP 相同；
- 带用户名密码的 Webshare HTTP 代理可用于 HTTPS 网站；
- 代理返回 407 时不会被误判为站点登录失败；
- 无效或消失的代理不再分配。

## 10. 第六阶段：可取消执行和断线恢复

### 10.1 取消令牌

每个槽位当前任务必须持有独立 `CancellationToken`。以下操作可以触发它：

- `CancelTask`；
- `EndSession.finish_current_task=false`；
- `PauseNode.finish_current_task=false`；
- Worker 进程优雅退出；
- 会话达到最大时长；
- 代理连接被确认失效。

真实自动化等待页面、搜索、下载和文件稳定时必须周期性检查取消令牌。

### 10.2 取消后的文件处理

- 浏览器停止当前下载；
- `.crdownload` 等本地临时文件保留到诊断清理阶段或安全删除；
- NAS 临时上传文件必须删除；
- 已经原子改名完成的文件不能直接删除，应上报文件证据交由 Master 决定；
- 取消结果必须使用当前执行的真实 `stage_version`。

### 10.3 本地执行现场

SQLite 除 Outbox 外增加执行现场表，至少保存：

```text
slot_index
session_id
task_id
execution_id
stage_version
task_status
staging_dir
nas_relative_path
source_sha256
updated_at
```

关键阶段写入现场：

- 已接受；
- 搜索中；
- 下载中；
- 本地文件完成；
- NAS 上传中；
- NAS 已原子落盘；
- 结果待上报；
- 已确认。

### 10.4 重连对账

`NodeOnline.active_executions` 和心跳中的 `active_executions` 必须来自内存与 SQLite 现场的合并结果。

Master 根据 `session_id + execution_id + task_id + stage_version` 判断：

- 仍是当前租约：续租并允许继续；
- 已被其他执行替代：下发取消；
- 已进入“待确认”：下发 NAS 核验或要求停止；
- 已完成：要求清理本地现场；
- 会话已结束：要求关闭浏览器。

### 10.5 验收标准

- 下载过程中断网 5 分钟，文件完成后结果可以补报；
- 下载过程中取消，任务在可控时间内停止；
- Worker 重启后不会盲目重新下载同一本书；
- 迟到结果不会覆盖新执行；
- 断线保护期内任务不会被另一 Worker 重复领取。

## 11. 第七阶段：NAS 强一致性

### 11.1 路径安全

必须分别验证：

- `nas_relative_path`；
- `uploading_file_name`；
- `final_file_name`。

文件名必须是单一文件名，禁止包含：

- `/` 或 `\`；
- `..`；
- Windows 盘符；
- UNC 根路径；
- 空字符串；
- `.` 或 `..`；
- NUL 和控制字符。

组合路径后需要确认规范化目标仍位于 `nas_mount` 内。

### 11.2 入库步骤

1. 校验本地文件格式和大小；
2. 计算本地 SHA-256；
3. 检查 NAS 剩余空间；
4. 复制到 NAS 同目录唯一临时名；
5. 刷新并关闭临时文件；
6. 重新读取 NAS 临时文件并计算 SHA-256；
7. 与源文件大小和哈希比较；
8. 使用不覆盖已存在文件的原子提交方式生成最终文件；
9. 最终路径已存在时重新校验；
10. 只有最终文件校验一致后才删除本地文件。

不能依赖 Unix `rename` 的覆盖行为。两个 Worker 同时完成同一本书时：

- 第一个成功提交；
- 第二个发现目标存在后比较哈希；
- 哈希一致则幂等成功；
- 哈希不同则转“待确认”，不得覆盖。

### 11.3 严格 NAS 核验

Worker 收到 `VerifyNasFile` 后必须：

- 验证相对路径安全；
- 读取指定目标文件，而不是任意文件；
- 返回真实挂载、可写、空间和延迟数据；
- 返回实际文件名、格式、大小和 SHA-256；
- 如果提供了期望值，逐项比较并在 `detail` 中说明。

Master 只有在以下全部满足时才能补记完成：

- 任务仍为“待确认”；
- 上报节点是被授权的在线节点；
- 路径与任务记录完全相同；
- 文件名与期望相同；
- 格式相同；
- 大小达到阈值；
- 有期望大小时必须一致；
- SHA-256 非空且格式合法；
- 有期望 SHA-256 时必须一致。

任何字段不符都不能登记 `book_files`。

### 11.4 验收标准

- 路径遍历、绝对路径和恶意文件名均被拒绝；
- NAS 复制中断不会出现最终文件；
- 两个 Worker 并发入库不会覆盖；
- 篡改文件后核验不会判为完成；
- NAS 空间不足时节点变为“存储异常”并停止领取下载会话。

## 12. 第八阶段：全局唯一图书和批次语义

### 12.1 图书合并事务

合并 `source → target` 前必须：

- 确认两本图书均存在；
- 确认 target 不是已合并记录；
- 防止循环合并；
- 锁定两本图书及相关任务、文件、批次关联；
- 如果 source 有执行中任务，拒绝合并或先安全结束执行。

同一事务中处理：

1. 把只存在于 source 的 `batch_books` 迁移到 target；
2. 如果同一批次已关联 target，删除 source 关联；
3. 迁移或合并 `book_tasks`；
4. 迁移 `book_files`；
5. 同格式文件同时存在时比较哈希，冲突则拒绝自动合并；
6. 更新所有展示状态；
7. 最后标记 source 为“已合并”。

### 12.2 批次取消

取消批次时，只有在该任务不再被任何非取消批次需要时，才能取消全局任务。

需要保护的其他批次状态包括：

- “待开始”；
- “执行中”；
- “已暂停”。

不能只检查“执行中”。

如果共享任务正在执行：

- 取消一个批次不能向 Worker 发送取消命令；
- 任务继续服务其他批次；
- 被取消批次仅改变自己的展示语义。

### 12.3 优先级

任务优先级取所有需要该任务且状态为“执行中”的批次中的最高优先级。排序规则保持：

1. 批次优先级降序；
2. 最早批次创建时间；
3. 最小导入行号。

必须增加 PostgreSQL 并发测试，证明多个 Worker 不会领取同一全局任务。

### 12.4 验收标准

- 同一本书出现在多个批次时只生成一条全局任务；
- 一个批次取消不会破坏其他待开始或暂停批次；
- 合并后 source 不再拥有独立可领取任务；
- 合并后批次进度和文件查询统一指向 target；
- 高优先级批次先被领取。

## 13. 第九阶段：TLS、mTLS 和管理安全

### 13.1 Worker 注册

Worker 本地生成私钥和 CSR：

1. 私钥只保存在 Worker；
2. CSR 的节点身份由 Master 重写或校验；
3. 注册请求发送 CSR；
4. Master 签发客户端证书；
5. Worker 保存证书和 Master 节点 CA；
6. 私钥文件设置为当前用户可读；
7. 身份文件不能打印节点 token。

注册日志禁止输出注册码、token、密码和私钥。当前注册入口打印注册码，需要删除。

### 13.2 gRPC TLS

Worker 使用 `Endpoint` 和 `ClientTlsConfig`：

- 加载服务端信任 CA；
- 加载客户端证书和私钥；
- 校验服务端域名；
- 生产模式禁止 `http://`；
- `require_client_cert=true` 时缺少任一证书文件应在启动时直接失败。

需要明确区分：

- Caddy 服务端证书的信任链；
- Master 签发 Worker 客户端证书的节点 CA。

不能把两者混为同一文件，除非部署方案明确由同一个受控 CA 同时签发。

### 13.3 Caddy

生产域名优先使用公开可信 TLS 证书。若使用内部 CA，必须提供明确的 Worker 信任安装流程。

客户端证书策略：

- 注册接口允许无客户端证书；
- `OpenLink` 必须要求客户端证书；
- Caddy 必须删除外部传入的伪造指纹头；
- 只把实际 TLS 客户端证书指纹传给 Master；
- Master 同时验证证书指纹和节点 token。

若同一 443 端口无法对注册 RPC 和 OpenLink 使用不同客户端证书策略，应拆分注册入口与 Worker 长连接入口，或在受控层实现明确路由。

### 13.4 JWT

每次鉴权至少检查：

- JWT 签名和过期时间；
- 用户仍然存在；
- 用户状态仍为“启用”；
- 当前数据库角色，而不是仅相信签发时角色。

改密、禁用用户或主动退出后，应通过令牌版本或撤销表使旧令牌失效。

### 13.5 管理后台静态资源

Vue 和 Tailwind 等生产资源必须随部署包本地提供，不能依赖公网 CDN。需要设置合理的 CSP、安全响应头和静态资源版本缓存。

### 13.6 验收标准

- 无客户端证书无法调用 `OpenLink`；
- A 节点证书配合 B 节点 token 无法通过认证；
- 吊销证书后旧连接在合理时间内失效；
- Worker 能正确验证云端域名证书；
- 禁用管理员后其旧 JWT 不能继续调用 API；
- 断开公网 CDN 后管理后台仍可加载。

## 21. 完成判定

本轮工作的最终完成条件不是“代码量增加”“模块存在”或“单元测试全绿”，而是：

> 在启用真实模式、真实 gRPC、真实 PostgreSQL、真实 Webshare 测试代理和真实 NAS 测试目录的情况下，一本指定测试图书能够由云端调度到任意可用 Worker，使用固定出口 IP正确下载，经过双重哈希校验原子写入 NAS，Master 幂等记录完成；同时取消、断网、重连和重复上报不会造成重复文件、重复额度或错误状态。

未达到该条件时，`实现进度.md` 必须如实标记为“未完成”或“部分完成”。
