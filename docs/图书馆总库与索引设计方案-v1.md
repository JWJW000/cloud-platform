# 图书馆总库与索引设计方案 V1

> 状态：设计稿，尚未实施  
> 日期：2026-08-25  
> 范围：云端图书总库、索引、增量导入、网页管理，以及与现有分布式下载平台的衔接

## 1. 目标

建立一个云端唯一图书总库。所有已知书目，无论来自哪一份 Excel、CSV 或后续新增来源，都先进入这个总库；系统持续计算哪些图书已经有经过校验的文件、哪些尚未下载，并把所有未满足项放入同一个全局下载任务池。

核心约束：

1. PostgreSQL 是业务事实的唯一来源；搜索引擎只是可重建的查询投影。
2. 系统只有一个持续运行的“补齐总库”任务，不以导入批次划分多个互不相干的下载任务。
3. “已下载”不是人工勾选值，而是由有效文件证据计算出来的状态。
4. 原始数据永久保留出处和原文；规范化、去重和合并不能破坏来源可追溯性。
5. 一本逻辑图书可以有多个版本、多个来源记录和多个可下载文件；不能把它们压成当前的一行四字段数据。
6. 新书单可随时增量导入；重复导入同一文件、同一来源记录不得产生重复书或重复下载任务。

暂不在本阶段执行：移动或修改 `/Volumes/PortableSSD/202608 (1)` 中的原始文件、批量导入、下载以及云端部署。

### 2.2 数据质量特征

设计必须覆盖以下真实情况：

- ISBN 可能为空、错误、带连字符、包含多个值，或实际是其他书目编号。
- 同一本书可能同时存在 PDF、EPUB、MOBI、AZW3、DJVU、FB2、TXT、CBZ 等文件。
- `md5 + filesize + extension` 描述的是来源文件候选，不等于本地已经下载。
- 专著与章节是不同层级；章节 DOI 不能作为整本书的 ISBN 去重替代品。
- 部分出版日期是 Excel 日期序号，部分是年份或自由文本。
- 标题、作者和出版社可能包含 HTML 实体、全半角差异、多语言字符和不同分隔符。
- 分类可能来自中图分类号 `scode/ztCode`、自由主题、关键词或完全缺失。
- 同名书、重印版、不同语言版、扫描版和文本版不能仅按规范化标题自动合并。
- AppleDouble `._*` 文件和 RAR 备份必须在扫描时排除。

因此，18,908,445 是“来源记录数”，不是最终唯一图书数。唯一图书数只能在完整导入、规范化与消歧后计算。

## 3. 总体架构

```text
移动硬盘 / 网页上传 / 对象存储
                │
                ▼
       流式导入与预检模块
                │
                ▼
     PostgreSQL 唯一事实库
  原始记录 → 规范图书 → 版本 → 来源文件
                │                │
                │                └── 全局获取目标/下载状态
                │                              │
                ▼                              ▼
      搜索投影 Outbox                  现有 Master 调度器
                │                              │
                ▼                              ▼
          OpenSearch                 异地 Worker 下载/校验
                │                              │
                └──────────┬───────────────────┘
                           ▼
                      Web 图书馆
                           │
                           ▼
                   NAS 或对象存储文件
```

沿用现有系统：

- Master、Worker、gRPC/mTLS、账号与代理资源管理；
- PostgreSQL 事务领取、租约、重试和掉线恢复；
- Worker Outbox、结果幂等、NAS 原子落盘与证据校验；
- 管理员登录、权限、审计日志和部署框架。

需要升级的部分：

- 当前 `books` 只有书名、作者、出版社、ISBN 和单一 `dedup_key`，不足以表达版本、章节和多个来源。
- 当前 `book_files` 与 `book_tasks` 只允许 PDF/EPUB，无法覆盖已有数据中的其他格式。
- 当前网页图书页只取最近 200 条，缺少服务端分页、组合过滤、统计和详情。
- 当前网页导入限制为 10 MiB、50,000 行 CSV，不适用于约 1,900 万条、4.2 GB 的 XLSX 总库。
- 当前 `download_batches` 不应继续充当业务主线；它只保留为导入来源、集合或历史追踪信息。

## 4. 图书馆核心模型

### 4.1 核心对象

| 对象 | 含义 | 示例 |
| --- | --- | --- |
| 作品 `work` | 抽象内容，不绑定某次出版 | 《算法导论》这一作品 |
| 版本 `edition` | 语言、出版社、年份、ISBN 等确定的一次出版 | 中文第三版、英文第四版 |
| 来源记录 `source_record` | 某个来源文件中的原始一行 | `cn/book_0001.xlsx` 第 2 行 |
| 来源文件 `source_asset` | 来源声称可以取得的一个具体文件 | 某 MD5 的 EPUB、大小 6 MB |
| 馆藏文件 `library_file` | 已真实下载并经过校验的文件 | NAS 上的 PDF、SHA-256 已验证 |
| 馆藏关联 `holding` | 某个馆藏文件满足某个版本/来源文件的关系 | 同一 PDF 同时命中两条重复书目 |
| 获取目标 `acquisition_target` | 总库希望补齐的版本/格式要求 | 该版本至少拥有一个首选格式 |
| 下载执行 `acquisition_execution` | Worker 的一次具体尝试 | 节点 A 第 2 槽尝试下载该 EPUB |
| 导入运行 `import_run` | 一次可恢复的数据导入 | 导入 `cn` 的第 8 个分片 |

关系：

```text
作品 1 ── N 版本 1 ── N 来源记录 1 ── N 来源文件
              │                              │
              ├── N 标识符                  └── N 馆藏关联
              ├── N 作者/主题                         │
              ├── N 获取目标 1 ── N 下载执行          ▼
              └──────────── N 馆藏关联 N ─────── 1 馆藏文件
```

章节作为 `work_type = chapter` 的作品保存，并通过 `parent_work_id` 指向所属专著；不能把 158 万章节当成 158 万本整书。

### 4.2 建议表结构

以下是逻辑结构，实施时再拆成正式迁移 SQL：

#### 来源与导入

- `catalog_sources`：来源名称、类型、许可/访问说明、默认优先级、启用状态。
- `import_files`：绝对来源标识、相对路径、文件 SHA-256、大小、工作表、结构版本、总行数。
- `import_runs`：状态、检查点、成功/隔离/重复数量、开始结束时间、错误摘要。
- `source_records`：`source_id`、`external_id`、文件/工作表/行号、原始 JSON、规范化字段、导入版本。
- `quarantined_records`：无法解析的原始行及原因，修复后可重新处理。

关键约束：

- `UNIQUE(source_id, external_id)`，有可靠来源 ID 时使用；
- `UNIQUE(import_file_id, sheet_name, row_number)`，保证同一文件重复导入幂等；
- `import_files.file_sha256` 用于识别完全相同文件；
- `source_records` 按来源或哈希分区，避免 2,000 万级单表维护失控。

#### 规范书目

- `works`：作品类型、首选标题、规范标题、主语言、消歧状态、合并指向。
- `editions`：作品、版本/卷册、语言、出版社、出版日期、版次、简介。
- `identifiers`：对象类型、对象 ID、标识符类型、原始值、规范值、有效性；支持 ISBN-10、ISBN-13、DOI、来源编号等多个值。
- `contributors` 与 `edition_contributors`：作者、译者、编者及顺序。
- `subjects` 与 `edition_subjects`：中图分类号、主题词、关键词及来源。
- `record_resolutions`：来源记录映射到哪个作品/版本、匹配方式、置信度、规则版本和人工裁决。

#### 文件与获取

- `source_assets`：来源记录、格式、声明大小、MD5、来源可用状态、下载定位信息。
- `library_files`：实际文件实体，包含格式、存储后端、相对路径/对象键、实际大小、SHA-256、可选 MD5、校验状态和入库时间。
- `holdings`：版本、来源文件和馆藏文件之间的关联，记录匹配方式、用途和是否满足获取策略。
- `acquisition_targets`：目标版本、格式策略、优先级、汇总状态、下一次尝试时间、活动租约。
- `acquisition_executions`：执行编号、目标、来源文件候选、Worker/槽位/账号/代理、阶段、结果和错误分类。
- `catalog_outbox`：事务内写入的搜索索引变更事件，异步投影到 OpenSearch。

关键约束：

- `UNIQUE(storage_backend, object_key)`；
- `UNIQUE(sha256)` 保证完全相同的文件实体只保存一条；多个版本或来源通过 `holdings` 关联同一实体；
- 一个获取目标同一时刻只能有一个有效租约；
- 同一来源 MD5 可映射到多个书目记录，但只下载一份实体文件，再建立多条 `holdings`；
- 文件格式不使用数据库封闭枚举，改用受控格式表，避免每增加一种格式都做迁移。

## 5. 去重与消歧

### 5.1 三层去重

1. **来源行幂等**：来源 ID 或“文件 + 工作表 + 行号”完全相同，直接命中原记录。
2. **文件实体去重**：MD5/声明大小用于来源侧候选去重；下载后以 SHA-256/实际大小作为馆藏事实。
3. **书目解析**：来源记录解析为作品和版本。解析结果带规则版本和置信度，允许以后重算。

### 5.2 自动匹配顺序

1. 合法 DOI：优先匹配章节或专著对象，且对象类型必须一致。
2. 合法 ISBN：匹配版本；多个 ISBN 拆成多条标识符，不把整个字符串当一个 ISBN。
3. 相同来源的稳定外部 ID：直接命中既有来源记录，不代表跨来源书目必然相同。
4. 规范标题 + 作者 + 出版社 + 年份/语言：只在信息足够且唯一时自动匹配。
5. 信息不足或存在多个候选：进入“待消歧”，不自动按标题合并。

禁止规则：

- 不按标题单字段全自动合并；
- 不把相同 ISBN 的不同文件格式压成一条文件；
- 不把章节 DOI 合并到整书作品；
- 不覆盖原始标题、作者、ISBN 和出处。

### 5.3 合并与拆分

管理员的合并/拆分只改变 `record_resolutions` 和规范对象关系。来源记录、下载执行和文件证据不删除。每次操作写审计日志，并触发搜索文档重建与获取状态重算。

## 6. “已下载”的严格定义

### 6.1 获取状态

| 状态 | 含义 |
| --- | --- |
| 待下载 | 获取目标尚无有效馆藏文件，也没有活动租约 |
| 排队中 | 已进入全局任务池，等待 Worker |
| 已领取 | Worker 已获得租约，尚未开始传输 |
| 下载中 | 正在取得文件 |
| 校验中 | 文件已落入临时区，正在核验大小、哈希和格式 |
| 已下载 | 至少一个满足策略的馆藏文件存在且校验为有效 |
| 暂时失败 | 允许重试，记录下次尝试时间 |
| 来源无效 | 当前来源候选不可用，可切换其他候选 |
| 人工确认 | 结果不确定、书目冲突或文件证据冲突 |
| 暂不获取 | 被策略排除，不等同于已下载或永久失败 |

“已下载”必须同时满足：

1. 版本存在指向 `library_files` 的有效 `holdings`；
2. 实际文件可访问；
3. 实际大小与数据库一致；
4. SHA-256 已计算并匹配；
5. 文件类型校验通过；
6. 状态为“有效”。

页面上的“图书已下载”是版本/作品的聚合结果。详情页必须继续展示到底是哪一种格式和哪个版本已满足，避免把“有任意一个 TXT”误显示成“所有版本都齐全”。

### 6.2 默认获取策略

V1 推荐：每个版本至少保存一个首选电子文件，格式优先级可配置，例如：

```text
EPUB/MOBI 类可重排格式：epub > azw3 > mobi > fb2
固定版式与扫描资料：pdf > djvu
其他格式：进入可配置候选或暂不获取
```

若业务最终要求“每个来源文件全部下载”，只需把获取目标从“版本 + 格式策略”切换为“每个 source_asset”，无需改变书目核心模型。

## 7. 索引体系

### 7.1 PostgreSQL 精确索引

PostgreSQL 负责所有必须正确的查询和约束：

- ISBN/DOI/来源 ID/MD5/SHA-256 使用 B-tree 唯一或普通索引；
- 获取状态使用 `(status, next_attempt_at, priority)` 领取索引；
- `待下载`、`活动租约`、`待消歧`使用部分索引；
- 来源记录按分区键和导入文件建立索引；
- 大列表全部使用游标分页，不使用深 `OFFSET`；
- 统计由增量汇总表维护，网页不能每次扫描 2,000 万行计算总数。

### 7.2 OpenSearch 全文与分面索引

OpenSearch 保存可重建的“版本搜索文档”，字段包括：

- 标题、别名、作者、出版社、简介、关键词；
- ISBN、DOI、来源编号；
- 语言、年份、分类、来源、可用格式；
- 获取状态、文件状态、是否待消歧；
- 作品/版本 ID 与更新时间。

用途：

- 中文、英文和其他语种全文搜索；
- 拼写/前缀/模糊检索；
- 按语言、年份、格式、分类、来源和下载状态做分面统计；
- 2,000 万级数据的稳定分页和排序。

同步采用事务 Outbox：PostgreSQL 提交书目变更时同事务写 `catalog_outbox`，索引器异步消费。网页详情和状态变更仍以 PostgreSQL 为准。索引可通过别名进行全量重建和原子切换。

## 8. 大规模导入设计

### 8.1 两条入口

1. **大库导入器**：在能读取移动硬盘或对象存储的机器运行，只读扫描目录，适用于本次 4.2 GB、约 1,900 万条数据。
2. **网页导入中心**：适用于后续较小的 CSV/XLSX 补充文件，支持字段映射、预检、确认和错误下载。

两条入口调用同一个深模块，不各自实现规范化和去重逻辑。

### 8.2 导入流水线

```text
发现文件 → 计算 SHA-256 → 识别工作表/结构 → 流式解析
        → 原始暂存/COPY → 字段规范化 → 来源幂等
        → 书目解析 → 获取目标重算 → 搜索 Outbox → 完成核对
```

要求：

- 不通过浏览器一次性上传数百 MB 文件；
- XLSX 流式读取，不能把整个工作簿装入内存；
- PostgreSQL 使用 `COPY` 或 25,000～100,000 行分块写入；
- 每个文件/工作表保存检查点，进程重启后可续传；
- 每个阶段记录输入、成功、重复、隔离和失败数量；
- 同一文件哈希重复导入时默认跳过；
- 导入完成必须满足“源行数 = 成功 + 重复 + 隔离”，否则不能标记完成；
- RAR 只作为备份，不在已有展开目录时重复导入；
- 原始移动硬盘始终只读，不移动、不重命名、不写回。

### 8.3 推荐导入顺序

1. 先导入 `cn/en/ot`，建立带文件 MD5 和格式的来源资产基线；
2. 再导入英文学术专著和章节，验证作品/章节层级；
3. 再导入 `图书书目1/2`，补充 ISBN、分类、关键词和简介；
4. 最后导入 `17w_vs_cn_完全未收录.csv` 作为集合关系，验证与总库的交叉匹配；
5. 完成后重建 OpenSearch 全量索引，并生成总库核对报告。

## 9. 一个持续运行的全局下载任务

系统不再以“上传一份 CSV = 新建一套下载任务”作为主要语义。

新的语义：

1. 导入只增加来源记录、规范书目和集合关系；
2. 获取策略根据新增/变化自动生成或更新 `acquisition_targets`；
3. 所有未满足目标进入同一个全局任务池；
4. Worker 只从这个池中领取下一项；
5. 新数据导入后自动汇入，不需要人工启动另一个批次；
6. 导入文件、原书单和历史批次只用于筛选、追溯和统计，不决定任务是否属于另一条业务线。

默认选择顺序：

1. 管理员显式优先级；
2. 失败冷却时间已到；
3. 有可用来源文件候选；
4. 来源质量和格式偏好；
5. 入库等待时间，避免长期饥饿。

下载失败时先在同一获取目标下切换其他 `source_asset`；所有候选都失败后才进入人工确认或长期冷却。现有租约、`FOR UPDATE SKIP LOCKED`、执行编号、Worker Outbox 和 NAS 证据闭环继续使用。

## 10. Web 图书馆信息架构

### 10.1 总览

首屏展示：

- 来源记录总数、规范作品数、版本数、来源文件数；
- 已下载、待下载、下载中、暂时失败、待人工确认；
- 今日/本周新增、下载成功数、有效字节数和吞吐；
- 在线 Worker、可用槽位、NAS/对象存储健康；
- 数据质量：无 ISBN、无作者、疑似重复、待消歧、隔离记录；
- 最近导入和最近失败趋势。

所有卡片可点击进入已带对应筛选条件的列表，不显示无法追溯的孤立数字。

### 10.2 图书检索

以搜索为主、表格为辅：

- 搜索框：标题、作者、ISBN、DOI、出版社、来源 ID；
- 左侧/顶部筛选：下载状态、语言、格式、年份、分类、来源、作品类型、数据质量；
- 结果列：标题/版本、作者、语言、出版社/年份、标识符、可用来源格式、馆藏格式、获取状态、更新时间；
- 支持保存筛选、导出当前结果、批量调整优先级和进入人工消歧；
- 使用游标分页，URL 保留查询条件，可分享和刷新。

### 10.3 图书详情

一个详情页分为：

1. 规范书目信息与所有版本；
2. 原始来源记录及“文件/工作表/行号”；
3. 标识符、作者、主题和分类；
4. 来源文件候选、MD5、声明大小和格式；
5. 已下载馆藏文件、路径/对象键、SHA-256 和校验时间；
6. 当前获取状态、失败原因和下一次重试；
7. 全部执行时间线、Worker、账号、代理和审计事件；
8. 合并、拆分、隐藏、重算匹配和重新下载操作。

### 10.4 导入中心

- 数据源列表与最近同步时间；
- 文件哈希、工作表、结构识别、行数和导入进度；
- 字段映射预览；
- 成功、重复、隔离、错误明细；
- 中断续传、重新处理隔离行、重建某一来源；
- 导入前后规范作品数和获取目标变化量。

### 10.5 下载中心

下载中心展示的是唯一全局任务池，不再以批次作为第一层导航：

- 队列、运行中、校验中、冷却、失败、人工确认；
- Worker/槽位、来源、格式、优先级、尝试次数；
- 全局暂停/恢复、单项重试、改优先级、切换来源；
- 按原始书单或导入文件筛选仍然可用，但只是视图条件。

## 11. 模块与接口

为避免把 2,000 万级导入、去重和状态计算散落到 HTTP 处理器、CLI 和 Worker 中，建议形成以下深模块：

### 11.1 `CatalogIngestion` 模块

小接口：

```text
preview(manifest) -> ImportPlan
run(plan_id) -> ImportRunId
resume(run_id) -> ImportRunId
```

实现内部隐藏 XLSX/CSV 解析、检查点、分块 COPY、幂等、隔离、规范化和 Outbox。网页和 CLI 只调用这个接口。

### 11.2 `CatalogResolution` 模块

```text
resolve(source_record_ids) -> ResolutionSummary
rebuild(rule_version, scope) -> ResolutionRunId
```

接口保证不丢原始记录、匹配可解释、规则有版本、结果可重算。单行去重函数不暴露给各调用方。

### 11.3 `CatalogSearch` 模块

```text
search(query, filters, cursor) -> SearchPage
get_detail(id) -> CatalogDetail
```

OpenSearch 是生产查询适配器，测试使用内存适配器；调用方不需要理解索引名称、分词器和聚合语法。

### 11.4 `Acquisition` 模块

```text
claim(worker_capabilities) -> Optional<Assignment>
report(execution_id, event) -> Decision
reconcile(target_id) -> AcquisitionState
```

接口隐藏候选来源选择、格式策略、租约、重试、文件证据和聚合状态。现有调度代码逐步迁入该模块，不在新架构外再叠一层平行队列。

### 11.5 `LibraryStorage` 模块

```text
commit(staged_file, expected_identity) -> VerifiedFile
verify(file_id) -> VerificationResult
```

NAS 和 S3/OSS 是两个实际存储适配器。接口统一要求 no-replace、路径/对象键安全、大小与 SHA-256 校验。

## 12. 云端部署建议

现有“4 核 8 GB、100 GB”配置适合调度平台，不适合把约 1,900 万条来源记录和全文索引全部放在同一台小机器。

V1 建议：

- PostgreSQL：8 vCPU、32 GB RAM、至少 500 GB NVMe，开启独立备份；
- OpenSearch：8 vCPU、32 GB RAM、至少 500 GB NVMe；生产可拆为独立主机，初期也可单节点验证；
- Master/API：4 vCPU、8 GB RAM；
- 导入器：可临时使用 8 vCPU、16～32 GB RAM 的机器，靠近数据源；
- 图书文件仍可落 NAS；如果要完全云端化，使用 S3/OSS 适配器，元数据模型不变；
- PostgreSQL 与 OpenSearch 不开放公网，只允许 Master、索引器和导入器访问；
- 备份必须同时包含 PostgreSQL、对象存储/NAS 清单和索引重建所需的规则版本；OpenSearch 本身可重建。

实际磁盘需要在全量预检中根据平均字段长度、索引分词量和增长率重新测算，再确定最终购买规格。

## 13. 实施阶段

### 阶段 A：事实库和导入骨架

- 建新表与分区；
- 实现 5 类 XLSX 结构和 2 份大书目的流式解析；
- 实现文件哈希、检查点、隔离和对账；
- 先导入小样本，验证一行不丢、重复导入不增量。

### 阶段 B：规范书目与搜索

- 实现 ISBN/DOI/MD5 规范化；
- 实现作品、版本、章节和来源文件解析；
- 建 OpenSearch 映射、Outbox 和全量重建；
- 完成服务端游标分页与分面查询。

### 阶段 C：Web 图书馆

- 总览、图书检索、详情、导入中心、数据质量中心；
- 下载状态和馆藏证据可下钻；
- 人工合并/拆分/确认有审计和可撤销路径。

### 阶段 D：接入唯一全局任务池

- 将现有 `book_tasks` 迁移为获取目标/执行模型；
- 导入后自动生成未满足目标；
- Worker 支持多格式能力声明与来源候选切换；
- 现有批次转换为集合/来源标签。

### 阶段 E：全量导入与验收

- 只读扫描移动硬盘并全量导入；
- 建立全量搜索索引；
- 对账来源行、隔离行、规范对象、获取目标和已下载文件；
- 执行断点续传、重复导入、Worker 掉线、NAS 断开和索引重建演练。

## 14. 验收标准

1. 18,908,445 条来源记录全部可核对为“成功、重复或隔离”，三者之和必须等于输入行数。
2. 任意来源记录可以在网页追溯到文件、工作表和行号。
3. 同一来源文件重复导入不会新增来源记录、规范版本或下载目标。
4. ISBN/DOI/MD5 精确查询可稳定返回；全文查询与筛选在目标规模下使用游标分页。
5. 标题相同但版本不同的书不会因标题单字段被自动合并。
6. 页面“已下载”记录都能下钻到可访问且 SHA-256 校验有效的馆藏文件。
7. 同一获取目标并发领取时只有一个 Worker 获得有效租约。
8. Worker、Master 或网络中断后，执行最终可收敛到已下载、待重试或人工确认，不永久卡在运行中。
9. 新增书单导入后自动进入同一个全局待下载池，不需要创建第二套业务任务。
10. OpenSearch 完全删除后可以仅依靠 PostgreSQL 和规则版本重建，不丢业务事实。

## 15. 仍需最终确认的三个业务选择

这些选择不阻塞阶段 A～C，但在接入下载前必须确认：

1. **获取粒度**：每个版本至少一个首选格式，还是每个来源文件都必须下载。V1 推荐前者。
2. **文件最终位置**：继续使用局域网 NAS，还是迁移到 S3/OSS 云对象存储。V1 建议先保留现有 NAS，同时实现存储接口以支持后续迁移。
3. **章节策略**：158 万章节是否独立下载，还是优先下载对应整本专著、章节只作为索引。V1 推荐章节进入总库索引，但优先整书，只有无整书来源时才独立获取章节。
