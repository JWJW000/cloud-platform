# 云端自动化平台生产化修复实施方案 V3

> 编写日期：2026-08-22  
> 适用目录：`cloud-platform/`  
> 文档性质：缺陷修复任务书、接口设计、测试计划、部署验收基线  
> 实施对象：后续负责修改代码的 Agent  
> 前置文档：`生产化修复实施方案-v2.md`  
> 当前结论：代码能够编译、单元测试基本通过，但仍不具备生产部署条件

## 1. 文档目标

本文件只处理 V2 实现后仍然存在的问题，不重复已经正确完成的模块。

修复后的系统必须真实满足以下闭环：

1. Worker 在本机生成私钥和 CSR，通过注册入口领取客户端证书；
2. Worker 验证云端服务端证书，并使用客户端证书建立 mTLS 长连接；
3. Master 同时校验客户端证书、节点 token、节点状态和证书吊销状态；
4. Worker 断网或进程重启后，内存状态、SQLite 现场和 Master 租约能够完成对账；
5. 同一本书、同一格式只生成一份 NAS 文件，并发 Worker 不得互相覆盖；
6. 一本书从登录到下载完成始终绑定同一个 Webshare 出口 IP；
7. 批次取消不会破坏其他仍需要该全局任务的批次；
8. 管理员禁用、改密或退出后，旧会话立即失效；
9. PostgreSQL、gRPC、代理、NAS 和前端安全测试真实执行，不得以“跳过后显示通过”代替；
10. 所有业务状态和业务枚举值使用中文，技术协议标识除外。

任何一项没有真实测试证据，都不能在 `实现进度.md` 中标记为“完成”。

## 3. 不可变业务约束

### 3.1 Worker 与槽位

- Worker 数量指物理电脑数量，不是浏览器数量；
- 第一阶段预计约 5 台物理 Worker；
- 每台 Worker 可以配置不同槽位上限；
- 本地 `requested_slots` 是设备安全上限；
- Master 管理员配置是实际启用上限；
- 实际槽位数取两者较小值；
- 缩容不能强杀正在写 NAS 的任务；
- 被停用的槽位在当前任务安全结束后退出。

### 3.2 NAS

- Worker 与同一台 NAS 位于同一局域网；
- 不同 Worker 可使用不同本地挂载路径；
- Master 只保存 NAS 相对路径，不保存某台电脑的绝对挂载路径；
- 文件由 Worker 直接写入 NAS，不经过云服务器中转；
- 同一本书、同一格式全局只保存一份有效文件；
- 不同哈希的同名文件不得自动覆盖；
- 已成功提交的最终文件不得因任务取消而删除。

### 3.3 Webshare 代理

- 继续使用 Webshare；
- 每个执行会话固定绑定一个代理；
- 一本书的登录、搜索、点击下载和文件完成必须使用同一个出口 IP；
- 下载过程中不得静默轮换代理；
- 代理失效时结束当前会话，由 Master 分配新会话；
- Webshare 已失效或已消失的代理不得再分配给新会话。

### 3.4 中文值

必须使用中文的值包括：

- 账号状态；
- Worker 状态；
- 槽位状态；
- 批次状态；
- 任务状态；
- 会话状态；
- 代理状态；
- 执行结果；
- 图书核验状态；
- 告警级别；
- 操作来源；
- 业务阶段和业务裁决。

以下技术标识不强制翻译：

- `pdf`、`epub`；
- `http`、`https`、`socks5`；
- UUID、SHA-256、IP、端口；
- Windows、macOS、Linux；
- Webshare 品牌名；
- gRPC、JWT、CSP 等协议或技术名。

当前 `OperationSource::Worker => "Worker"` 应改为“工作节点”或“节点”。数据库迁移必须同步已有值。

## 4. 威胁模型与信任边界

### 4.1 需要保护的资产

- 管理员账号与会话；
- Worker 节点 token、客户端私钥和证书；
- Webshare 用户名、密码和 API Key；
- 图书站点账号密码及每日额度；
- NAS 路径、文件内容和文件哈希；
- 任务租约、执行编号和阶段版本；
- 管理操作日志和下载记录。

### 4.2 信任边界

```text
管理员浏览器
    │ HTTPS + 安全会话 Cookie
    ▼
Caddy / 公网入口
    │ HTTP 内网反代
    ▼
Master API ───────── PostgreSQL

异地 Worker
    │ TLS / mTLS + 节点 token
    ▼
Caddy gRPC 入口
    │ h2c + 受信证书指纹头
    ▼
Master WorkerLink

Worker 自动化进程
    │ 本机回环代理
    ▼
Webshare ─────────── 目标图书站点

Worker
    │ 局域网挂载
    ▼
共享 NAS
```

### 4.3 主要威胁

| 威胁 | 当前风险 | 必须采取的控制 |
| --- | --- | --- |
| 冒充 Worker | token 泄漏后可连接 | mTLS、token、证书归属三重校验 |
| 伪造证书指纹 | 外部客户端写入同名头 | Caddy 删除外部头，只注入真实 TLS 指纹 |
| NAS 文件篡改或覆盖 | 并发 `rename` 可覆盖 | 不覆盖原子提交、双重哈希、冲突转待确认 |
| 路径逃逸 | 文件名参数未单独校验 | 路径组件校验、叶子文件名校验、挂载根 containment |
| 旧 JWT 越权 | 只信任 Claims | 每请求查库、会话撤销、当前角色校验 |
| 登录爆破 | 无登录限流 | IP 与用户名双维度限流、失败审计 |
| 代理凭据泄漏 | 日志或错误可能带凭据 | 密文存储、日志脱敏、错误不回显凭据 |
| 任务重复完成 | 重连现场未对账 | SQLite + Master 租约裁决 + 幂等事件 |
| 测试假绿 | 数据库用例直接返回 | 强制数据库环境、CI 中禁止跳过 |

## 6. R1：先修复测试假绿机制

### 6.1 当前问题

`crates/master-server/tests/support/mod.rs` 声称：

- 没有数据库时默认跳过；
- 设置 `REQUIRE_TEST_DATABASE=1` 后应直接失败。

但宏没有读取 `REQUIRE_TEST_DATABASE`。即使设置该变量，12 个 PostgreSQL 测试仍然直接 `return`，Cargo 最终显示“12 passed”。

### 6.2 必须修改

修改 `require_db!`：

```rust
None => {
    if std::env::var("REQUIRE_TEST_DATABASE").as_deref() == Ok("1") {
        panic!("要求执行 PostgreSQL 集成测试，但未设置 TEST_DATABASE_URL/DATABASE_URL");
    }
    eprintln!("跳过：未配置测试数据库");
    return;
}
```

同时增加统一的测试环境摘要：

```text
PostgreSQL 集成测试：已执行 / 已跳过 / 禁止跳过但配置缺失
NAS 集成测试：已执行 / 已跳过
代理集成测试：已执行 / 已跳过
浏览器端到端测试：已执行 / 已跳过
```

CI 的生产验收 Job 必须设置：

```text
REQUIRE_TEST_DATABASE=1
TEST_DATABASE_URL=postgres://...
```

### 6.3 验收标准

- 未配置数据库且未要求强制执行时，可以跳过，但输出必须明确；
- 设置 `REQUIRE_TEST_DATABASE=1` 且无连接串时，测试退出码必须非 0；
- 配置真实 PostgreSQL 后，迁移和 SQL 全部真实执行；
- 测试统计不得再把提前 `return` 描述成生产验收通过。

## 7. R2：完成 TLS 和 mTLS 全链路

### 7.1 证书体系必须分离

生产环境至少有两条信任链：

1. **云端服务端证书信任链**：用于 Worker 和浏览器验证 Caddy；
2. **节点客户端证书信任链**：Master 的 Node CA 为 Worker 签发客户端证书。

推荐方案：

- 云端域名使用公开 CA 证书；
- Caddy 使用 Node CA 验证 Worker 客户端证书；
- Worker 使用系统根证书验证云端域名；
- 只有无法使用公开域名时，才额外向 Worker 分发 Caddy 内部根证书。

不得把 Node CA 证书当作 Caddy 服务端证书根证书，除非部署方案明确由同一受控 CA 同时承担两种用途并记录风险。

### 7.2 推荐拆分两个入口

建议使用两个域名：

```text
enroll.example.com  注册入口，只要求服务端 TLS
worker.example.com  OpenLink 入口，强制 mTLS
admin.example.com   管理后台 HTTPS
```

如果必须共用一个域名，则 Caddy 必须按 gRPC 方法精确区分：

```text
/platform.v1.WorkerLink/Enroll     可无客户端证书
/platform.v1.WorkerLink/OpenLink   必须有有效客户端证书
```

不能使用当前“所有 gRPC 都只是 request 客户端证书，再由默认关闭的开关决定是否放行”的生产配置。

### 7.3 Worker 注册流程

修改 `worker-agent/src/main.rs`，注册时执行：

1. 在 Worker 本机生成私钥；
2. 私钥使用 PKCS#8 PEM 保存；
3. 文件权限设置为当前用户可读写；Unix 为 `0600`；
4. 使用私钥生成 CSR；
5. CSR 的主题中写入机器可读名称，但不能把 token 或注册码写入 CSR；
6. 调用 `Enroll`；
7. 验证响应中 `certificate_pem` 和 `ca_certificate_pem` 非空；
8. 验证返回证书的公钥与本地私钥匹配；
9. 原子写入客户端证书和 Node CA；
10. 最后才写入身份文件；
11. 任一步失败均不得留下“有 token、无可用证书”的半注册状态。

建议新增：

```rust
pub struct WorkerIdentityPaths {
    pub identity_file: PathBuf,
    pub client_key_file: PathBuf,
    pub client_cert_file: PathBuf,
    pub node_ca_file: PathBuf,
}
```

建议身份文件只保存：

```json
{
  "node_id": "...",
  "node_token": "...",
  "node_name": "...",
  "certificate_fingerprint": "..."
}
```

私钥不得写入 JSON，也不得打印到日志。

### 7.4 Worker TLS Channel 工厂

新增统一连接模块，例如：

```text
worker-agent/src/tls.rs
```

提供两个入口：

```rust
pub async fn enrollment_channel(config: &WorkerConfig) -> Result<Channel>;
pub async fn worker_link_channel(config: &WorkerConfig) -> Result<Channel>;
```

`enrollment_channel`：

- 必须验证服务端证书；
- 不加载客户端证书；
- 设置连接超时；
- 设置域名；
- 禁止生产环境 `http://`。

`worker_link_channel`：

- 加载客户端证书和私钥；
- 加载服务端 CA 或使用系统根证书；
- 使用 `ClientTlsConfig::identity(...)`；
- 使用 `ClientTlsConfig::ca_certificate(...)` 或系统根；
- 验证端点域名；
- 文件缺失、权限过宽或证书无效时直接拒绝启动；
- 不能静默退回明文或 token-only 模式。

### 7.5 Master 与 Caddy

Caddy 必须：

- 删除外部传入的 `x-client-cert-fingerprint`；
- 只使用实际 TLS 客户端证书计算 SHA-256 指纹；
- 对 OpenLink 强制客户端证书；
- 使用 Node CA 验证客户端证书链；
- 不允许过期或吊销证书建立新连接；
- 对注册入口只做服务端 TLS；
- 为管理后台设置公开可信服务端证书。

Master 必须：

- 生产模式强制 `require_client_cert = true`；
- 启动时发现生产模式关闭该开关必须失败；
- 同时验证节点 token 和证书指纹；
- 验证证书归属当前 `node_id`；
- 验证节点未禁用；
- 验证证书未过期、未吊销；
- 证书 A + token B 必须失败；
- 吊销证书后主动关闭已有连接，不能只阻止下次重连。

### 7.6 证书轮换

至少支持以下运维流程：

- 证书到期前 30 天告警；
- 管理员为节点签发新证书；
- Worker 原子替换证书；
- 新证书验证成功后吊销旧证书；
- 私钥丢失时必须重新注册或走受控换证流程；
- 节点被禁用时吊销其全部客户端证书并断开当前链路。

### 7.7 mTLS 测试

必须覆盖：

- 只有服务端 TLS、无客户端证书：Enroll 成功；
- 无客户端证书：OpenLink 失败；
- 有效证书 + 正确 token：成功；
- A 节点证书 + B 节点 token：失败；
- 伪造指纹头：Caddy 清除后失败；
- 已吊销证书：失败；
- 过期证书：失败；
- Worker 不信任服务端证书：失败；
- Worker 域名不匹配：失败；
- 日志中不出现私钥、注册码、token 或代理密码。

## 8. R3：NAS 不覆盖原子提交

### 8.1 当前问题

现有逻辑是：

```text
检查目标不存在 → 复制临时文件 → rename 到最终路径
```

检查和 `rename` 不是一个原子操作。两个 Worker 可以同时通过检查，后一个 `rename` 在 Unix 上覆盖前一个文件。

### 8.2 路径模型必须收敛

`nas_relative_path` 是唯一最终路径来源。

不得同时信任：

- `nas_relative_path`；
- `final_file_name`；
- `uploading_file_name`。

建议重构函数签名：

```rust
pub async fn ingest_file(
    storage: &StorageConfig,
    local_temp_file: &Path,
    nas_relative_path: &str,
    task_id: Uuid,
    execution_id: Uuid,
    node_id: Uuid,
    minimum_bytes: u64,
) -> Result<IngestOutcome>;
```

最终文件名从 `nas_relative_path.file_name()` 推导；临时文件名由本地可信代码生成：

```text
.<最终文件名>.上传中-<task_id>-<execution_id>-<node_id>-<随机数>
```

新增 `validate_leaf_file_name`，拒绝：

- 空值；
- `.` 和 `..`；
- `/` 和 `\`；
- Windows 盘符；
- NUL 和控制字符；
- 超过文件系统安全长度的名称；
- 任何会产生多个路径组件的值。

### 8.3 挂载根 containment

仅检查字符串中的 `..` 不够。还必须：

1. 规范化挂载根；
2. 创建目标父目录；
3. 规范化目标父目录；
4. 确认目标父目录仍位于挂载根内；
5. 拒绝中间路径中的符号链接或重解析点逃逸；
6. 最终文件只能在已验证目录句柄下创建。

在可行的平台上优先使用目录句柄相对操作，减少校验与打开之间的 TOCTOU 风险。

### 8.4 提交流程

完整流程：

1. 校验本地暂存文件存在且是普通文件；
2. 校验格式魔数、文件大小和目标书名；
3. 计算本地文件 SHA-256；
4. 检查 NAS 剩余空间；
5. 在最终目录使用独占创建方式创建唯一临时文件；
6. 流式复制，并记录实际复制字节数；
7. 对临时文件执行 `sync_all`；
8. 重新读取 NAS 临时文件并计算 SHA-256；
9. 确认大小和哈希与本地一致；
10. 使用“不覆盖”的原子方式提交最终文件；
11. 对目标目录执行同步（平台支持时）；
12. 再次读取最终文件元数据和 SHA-256；
13. 只有最终复核成功后，才能删除本地暂存文件；
14. 清理临时文件和锁文件。

### 8.5 跨平台不覆盖策略

实现一个小而明确的平台抽象：

```rust
pub enum CommitOutcome {
    Created,
    AlreadyExists,
}

pub async fn commit_noreplace(temp: &Path, final_path: &Path) -> Result<CommitOutcome>;
```

可选实现顺序：

- Linux：`renameat2(..., RENAME_NOREPLACE)`；
- macOS：`renamex_np(..., RENAME_EXCL)`；
- Windows：不带覆盖标志的原子 Move API；
- 文件系统支持硬链接时：`hard_link(temp, final)`，成功后删除临时文件；
- NAS 不支持上述语义时：使用同目录独占锁文件协议，并通过真实并发测试证明行为。

禁止：

- 普通 `rename` 后假设不会覆盖；
- 删除现有目标再重命名；
- 先 `exists()` 再无条件 `rename()`；
- 哈希不同时自动添加 `(1)`、`副本` 等文件名；
- 使用数据库锁代替 NAS 文件系统锁，因为 Worker 可能断网但仍在写 NAS。

### 8.6 已存在目标的处理

如果不覆盖提交返回 `AlreadyExists`：

1. 读取最终文件大小和 SHA-256；
2. 与本次临时文件比较；
3. 哈希一致：视为幂等成功，删除本次临时文件；
4. 哈希不同：保留最终文件，删除或隔离本次临时文件，任务转“待确认”；
5. 记录冲突告警，包含任务、执行、节点、相对路径和两个哈希；
6. 日志不得包含本地账号或代理凭据。

### 8.7 NAS 并发测试

必须在真实测试目录中并发运行：

- 两个不同内容写同一最终路径；
- 两个相同内容写同一最终路径；
- 10 个并发执行写同一最终路径；
- 提交前进程终止；
- 复制中断；
- NAS 空间不足；
- 目标目录包含符号链接；
- 文件名含 `..`、绝对路径、UNC、盘符和分隔符；
- Windows、macOS、Linux 至少分别跑一次平台测试；
- 实际使用的 SMB/NFS/NAS 挂载协议必须跑一次真实设备测试。

验收结果必须证明：最终路径从不被不同哈希覆盖，且不会留下被误认为完成的半文件。

## 9. R4：重启现场恢复与 Master 对账

### 9.1 当前问题

Worker 已写 `execution_state`，但上线和心跳只上报内存中的 `SlotManager`。Master 收到 `NodeOnline.active_executions` 后只记录数量，没有逐个裁决。

因此进程重启后：

- SQLite 现场被忽略；
- Master 不知道 Worker 曾经下载或落盘；
- 现场记录不会清理；
- 任务可能重复下载；
- 已落盘文件可能长期停在“待确认”。

### 9.2 Worker 启动恢复

启动时必须先读取 SQLite，再允许申请新会话：

```text
读取 execution_state
→ 校验每条记录格式
→ 检查暂存目录和 NAS 文件
→ 与当前内存执行合并
→ 建立恢复快照
→ 连接 Master
→ NodeOnline 上报恢复快照
→ 等待 Master 裁决
→ 裁决结束后才申请新会话
```

合并键为 `execution_id`。如果内存和 SQLite 同时存在：

- `task_id`、`session_id`、`stage_version` 必须一致；
- 阶段取更靠后的可信阶段；
- 冲突时不得自动继续，转本地隔离并告警。

### 9.3 可恢复阶段

| SQLite 阶段 | 重启后的本地处理 |
| --- | --- |
| 已接受 | 不自动重新下载，等待 Master 裁决 |
| 搜索中 | 浏览器现场不可恢复，等待 Master 放回任务 |
| 下载中 | 检查任务暂存目录；部分文件清理后等待重新分配 |
| 本地文件完成 | 复核本地文件后，可按 Master 裁决继续入库 |
| NAS上传中 | 检查唯一临时文件，复核后继续或清理 |
| NAS已原子落盘 | 复核最终 NAS 文件并请求 Master 核验 |
| 结果待上报 | 依靠 Outbox 立即重放结果 |
| 已确认 | 删除执行现场，不再上报 |

不得声称浏览器进程重启后可以无条件续传。无法证明安全续传时，应停止旧执行并由 Master 重新分配。

### 9.4 协议扩展

建议新增明确的下行对账消息，不要借用日志或 `CancelTask.reason` 表达裁决：

```proto
message ExecutionReconcileDecision {
  string execution_id = 1;
  string task_id = 2;
  uint32 stage_version = 3;
  string decision = 4;  // 继续入库 / 重放结果 / 核验NAS / 停止并清理 / 保留待人工处理
  string reason = 5;
}
```

如需批量响应，可以增加：

```proto
message ReconcileExecutions {
  repeated ExecutionReconcileDecision decisions = 1;
  bool reconciliation_complete = 2;
}
```

业务值必须使用中文；proto 字段名仍保持技术英文。

### 9.5 Master 对账规则

Master 对每条现场查询：

- 任务当前状态；
- 当前 `stage_version`；
- 当前 `lease_execution_id`；
- 当前 `lease_session_id`；
- 执行记录是否已经完成；
- 是否已有可信 `book_files`；
- 是否处于断线保护期；
- 管理员是否已取消任务或节点。

裁决规则：

1. `execution_id`、租约和版本全部匹配：允许继续；
2. 结果已经被 Master 接受：通知 Worker 清理现场；
3. 任务已取消：停止并清理未提交临时文件；
4. 任务已被新世代领取：旧执行停止，迟到结果仅审计；
5. Worker 报告“NAS 已落盘”但 Master 未完成：下发严格 NAS 核验；
6. Worker 报告“结果待上报”：要求立即重放 Outbox；
7. 现场无法解释：任务转“待确认”，不得直接放回并重复下载。

### 9.6 心跳续租

当前心跳续租 SQL 的执行结果被忽略。应改为：

- 只有精确匹配任务、会话、执行和 `stage_version` 才续租；
- `rows_affected == 0` 时向 Worker 下发停止裁决；
- SQL 错误不能静默忽略，必须记录告警；
- 不合法 UUID 和非法阶段应记录协议错误；
- 心跳中的执行集合必须来自“内存 + SQLite 现场”的合并结果。

### 9.7 ACK 与现场清理

不能只删除 Outbox 事件。

收到 `EventAck.accepted = true` 时：

1. 在删除前读取 Outbox 原消息；
2. 如果是 `TaskResult`，取得 `execution_id`；
3. 将对应执行现场更新为“已确认”；
4. 删除执行现场；
5. 删除 Outbox；
6. 上述操作应在同一个 SQLite 事务内完成。

可以新增：

```rust
pub fn acknowledge_event(&self, event_id: &str) -> Result<AcknowledgedEvent>;
```

返回已确认事件类型和执行编号，避免依赖 `evt-res-<execution_id>` 字符串解析。

### 9.8 重连测试

必须覆盖每个阶段的进程终止：

- 接受任务后；
- 搜索中；
- 下载一半；
- 本地文件完成；
- NAS 复制一半；
- NAS 已提交但结果未发；
- 结果已发但 ACK 未到；
- ACK 到达但 SQLite 清理前。

每个用例验证：

- 不重复消耗账号额度；
- 不覆盖 NAS 文件；
- 不错误完成新世代任务；
- Outbox 最终清空；
- `execution_state` 最终清空；
- Master 和 Worker 最终状态一致。

## 10. R5：批次取消与共享任务

### 10.1 共享判断范围

取消批次时，只有全局任务不再被任何以下状态的其他批次需要，才允许取消任务：

- 待开始；
- 执行中；
- 已暂停。

不能只检查“执行中”。

### 10.2 事务流程

`cancel_batch` 必须在一个事务内：

1. `FOR UPDATE` 锁定批次；
2. 校验批次可以取消；
3. 把批次改为“已取消”；
4. 锁定本批次关联的全局任务；
5. 对每个任务查询其他非取消需求；
6. 有其他需求：任务保持原状态，不设置 `cancel_requested`；
7. 无其他需求且任务待处理：直接改为“已取消”；
8. 无其他需求且任务执行中：设置 `cancel_requested = true`，保留当前租约并记录下发目标；
9. 提交事务；
10. 事务提交后向对应在线 Worker 下发 `CancelTask`；
11. 离线 Worker 依靠重连对账收到停止裁决；
12. 发布批次和任务变更事件。

存储函数不能只返回数量，建议返回：

```rust
pub struct BatchCancelOutcome {
    pub batch_id: Uuid,
    pub directly_cancelled_task_ids: Vec<Uuid>,
    pub running_targets: Vec<RunningCancelTarget>,
    pub shared_task_ids: Vec<Uuid>,
}

pub struct RunningCancelTarget {
    pub task_id: Uuid,
    pub node_id: Uuid,
    pub session_id: Uuid,
    pub execution_id: Uuid,
}
```

下发取消消息必须携带 `execution_id`，避免误杀同任务的新执行。

### 10.3 取消后的结果

- Worker 在 NAS 提交前收到取消：删除本次临时文件，上报“取消”；
- Worker 已完成最终 NAS 提交：不得删除最终文件，应上报文件证据；
- Master 已设置 `cancel_requested` 后收到成功结果：不能直接按普通成功处理，应按是否已可靠落盘决定“完成”或“待确认”；
- 取消消息迟到且任务已进入新世代：旧 Worker 只能停止自己的 `execution_id`；
- 共享任务不得因一个批次取消而停止。

### 10.4 测试

必须覆盖：

- 单独批次中的待处理任务；
- 单独批次中的执行中任务；
- 与其他待开始批次共享；
- 与其他执行中批次共享；
- 与其他已暂停批次共享；
- 取消消息发送失败；
- Worker 离线；
- 取消与成功结果并发；
- 取消与新租约并发；
- 重复取消幂等。

## 11. R6：管理端认证和浏览器安全

### 11.1 JWT 验证不能只信任 Claims

每次受保护请求必须检查：

1. JWT 签名；
2. `exp`；
3. `nbf`，如使用；
4. `sub` 格式；
5. 用户仍然存在；
6. 用户状态仍为“启用”；
7. 数据库中的当前角色；
8. 会话尚未撤销；
9. token 版本仍匹配。

`AuthenticatedUser` 应通过用户 ID 查库，不应只按 Claims 中的用户名查找。

### 11.2 推荐会话模型

新增迁移：

```sql
ALTER TABLE users ADD COLUMN token_version BIGINT NOT NULL DEFAULT 1;

CREATE TABLE admin_sessions (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL REFERENCES users(id),
    token_hash TEXT NOT NULL UNIQUE,
    issued_at TIMESTAMPTZ NOT NULL,
    expires_at TIMESTAMPTZ NOT NULL,
    revoked_at TIMESTAMPTZ,
    revoke_reason TEXT,
    last_seen_at TIMESTAMPTZ,
    user_agent_hash TEXT,
    ip_prefix TEXT
);
```

JWT 至少包含：

```text
sub 用户ID
jti 会话ID
ver token_version
iat
exp
```

角色不应作为最终授权依据。即使保留在 Claims 中用于展示，授权也必须使用数据库当前角色。

### 11.3 会话失效规则

- 主动退出：只撤销当前 `jti`；
- 改密：增加 `token_version` 并撤销该用户全部会话；
- 禁用用户：增加 `token_version` 并撤销全部会话；
- 修改角色：增加 `token_version` 并撤销全部会话；
- 删除用户：全部会话失效；
- 超时会话定期删除或归档；
- 撤销动作写入管理员安全审计日志。

### 11.4 浏览器存储

禁止把长期认证 token 放在 `localStorage`。

推荐使用：

```text
Set-Cookie: 管理会话=<随机会话令牌>;
HttpOnly;
Secure;
SameSite=Strict 或 Lax;
Path=/;
Max-Age=...
```

如果使用 Cookie，会引入 CSRF 边界。所有写操作必须增加：

- `SameSite`；
- `Origin` / `Referer` 校验；
- CSRF token 或双提交机制；
- 只允许 JSON Content-Type；
- 不允许跨站简单表单触发状态修改。

### 11.5 SSE

`/api/events` 必须鉴权。

使用 HttpOnly Cookie 后，原生 `EventSource` 可以在同源请求中自动携带 Cookie。服务端必须：

- 提取认证会话；
- 检查用户仍有效；
- 对单用户连接数设上限；
- 设置心跳；
- 连接关闭时释放订阅；
- 不向只读用户推送其无权查看的敏感信息；
- 事件载荷只包含刷新所需的最小字段。

当前前端只注册 `onmessage`，但服务端发送了自定义事件名。应选择一种统一方案：

- 服务端统一发送默认 `message`；或
- 前端为“节点变更”“批次变更”“任务变更”等逐个 `addEventListener`。

### 11.6 CORS

同源部署时优先不启用 CORS。

确有跨域需求时：

- 从配置读取精确允许来源；
- 禁止 `allow_origin(Any)`；
- 只允许实际使用的方法；
- 只允许实际使用的请求头；
- 使用 Cookie 时开启 credentials，并禁止通配符来源；
- 拒绝 `null` Origin；
- 增加 CORS 自动测试。

### 11.7 登录限流

至少实现：

- 单 IP：15 分钟最多 20 次失败；
- 单用户名：15 分钟最多 10 次失败；
- 逐步退避；
- 成功登录后清除或衰减计数；
- 429 返回中文通用提示；
- 不泄漏用户名是否存在；
- 失败和锁定写安全审计日志；
- 反向代理 IP 只信任受控 Caddy 传递的地址。

限流存储第一阶段可使用 Master 内存，但多实例部署前必须迁移到 Redis 或数据库。

### 11.8 安全响应头

Caddy 或 Axum 至少设置：

```text
Strict-Transport-Security
Content-Security-Policy
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: no-referrer
Permissions-Policy
Cache-Control（按资源类型区分）
```

建议 CSP：

```text
default-src 'self';
script-src 'self';
style-src 'self';
img-src 'self' data:;
connect-src 'self';
object-src 'none';
base-uri 'self';
frame-ancestors 'none';
form-action 'self';
```

不要为了保留内联脚本直接添加宽泛的 `'unsafe-inline'`。应把脚本和样式构建成独立静态文件。

### 11.9 本地化前端依赖

移除：

```html
https://cdn.tailwindcss.com
https://unpkg.com/vue@3/dist/vue.global.prod.js
```

将 `web-admin` 改为可重复构建的本地项目：

```text
web-admin/
├── package.json
├── 锁文件
├── src/
└── dist/
```

要求：

- 固定包管理器和版本；
- 提交唯一锁文件；
- CI 使用 frozen/immutable install；
- 生产镜像只复制 `dist`；
- 带哈希的静态资源长期缓存；
- `index.html` 不缓存或短缓存；
- 断开公网后后台仍可加载和登录。

### 11.10 管理端测试

- 禁用用户后旧会话立即 401；
- 改密后全部旧会话失效；
- 角色变更后旧权限不能继续使用；
- 主动退出后当前会话失效；
- 只读用户不能写；
- 未认证不能订阅 SSE；
- 非允许 Origin 被拒绝；
- 登录限流触发 429；
- 响应包含安全头；
- 前端无公网依赖；
- 页面不再从 `localStorage` 读取认证 token。

## 12. R7：重写本地代理转发

### 12.1 当前问题

现有实现：

- 只读取一次、最多 4096 字节请求头；
- 请求头不完整时仍继续处理；
- 只给首个普通 HTTP 请求注入认证；
- keep-alive 后续请求未经认证直接透传；
- 没有请求头大小、读取时间和空闲连接限制；
- 上游响应也只在 CONNECT 阶段读取一次固定缓冲区。

这会导致代理 407、中途断流或异常内存/连接占用。

### 12.2 实现原则

不要继续扩展手写字符串代理解析器。优先：

1. 使用成熟、支持异步 HTTP/1.1 解析的库；
2. 对 CONNECT 建立一次认证隧道后进行字节透传；
3. 对普通 HTTP keep-alive，逐请求解析并逐请求注入认证；
4. 正确处理 Content-Length 和 chunked body；
5. 删除客户端自带的 `Proxy-Authorization`，再注入当前会话凭据；
6. 请求头最大 64 KiB；
7. 首包、连接、空闲和总时长均有超时；
8. 限制每槽位并发连接数；
9. 只监听 `127.0.0.1` / `::1`；
10. 日志不得打印认证头。

### 12.3 固定 IP 约束

`LocalProxyServer` 生命周期必须严格属于执行会话：

```text
CreateSession
→ 锁定一个 Webshare 代理
→ 启动本地代理端口
→ 浏览器使用该端口
→ 会话内所有图书都使用该代理
→ 代理错误时结束会话
→ 释放代理
```

一本书执行过程中不得响应动态代理配置变更。新配置只能影响新会话。

### 12.4 代理测试服务器

新增测试代理，记录：

- 每个 TCP 连接收到的认证头；
- CONNECT 目标；
- 普通 HTTP 请求数量；
- keep-alive 第二个请求是否仍带认证；
- 出口 IP 模拟值；
- 407、429、连接重置和超时行为。

必须覆盖：

- CONNECT 成功；
- CONNECT 407；
- 超过 4096 字节但小于上限的请求头；
- 超过最大请求头；
- 一个连接连续两个普通 HTTP 请求；
- chunked 请求；
- 上游半途关闭；
- 取消任务时隧道及时关闭；
- 用户名或密码含需要 Basic 编码的字符；
- 日志中无代理密码。

## 13. R8：Webshare 有效快照同步

### 13.1 当前问题

当前 `seen_ids` 在每一页内重新创建且最终未使用。`valid=false` 只被跳过，数据库里旧的可用记录不会失效；从 Webshare 列表消失的代理也不会停用。

### 13.2 正确同步流程

一次完整同步必须先抓取所有分页，再开启数据库事务：

1. 请求第一页；
2. 校验 `next` URL 仍属于 Webshare 官方域名和 HTTPS；
3. 抓取全部分页；
4. 建立全局 `seen_external_ids`；
5. 对 `valid=true` 项执行 upsert；
6. 对 `valid=false` 项标记为“异常”或“已停用”；
7. 对本次快照未出现、provider 为 Webshare 的旧代理标记“已停用”；
8. 已被会话占用的代理不强制中断当前任务，但立即禁止新分配；
9. 会话释放后保持停用；
10. 提交事务；
11. 记录新增、更新、失效、消失和保留数量。

建议为代理增加同步字段：

```text
last_seen_at
provider_valid
retire_after_release
sync_generation
```

管理员手工停用的代理不得因为下次 Webshare `valid=true` 自动恢复。需要区分：

- provider 状态；
- 管理员治理状态；
- 调度有效状态。

### 13.3 第三方 URL 安全

Webshare 返回的 `next` 属于外部输入，必须：

- 只允许 `https`；
- 主机名必须在 Webshare allowlist；
- 禁止跳转到任意域名；
- 请求设置连接和总超时；
- 限制最大分页数和最大代理数；
- 响应体设置大小上限；
- 错误日志不得包含 API Key。

### 13.4 测试

## 14. R9：严格 NAS 核验

### 14.1 期望证据必须有来源

当前 Master 下发 `VerifyNasFile` 时把 `expected_sha256` 留空，导致“严格核验”没有可比较的可信值。

当任务进入“待确认”时，应保存候选证据：

```text
expected_nas_relative_path
expected_file_name
expected_format
expected_size_bytes
expected_sha256
evidence_execution_id
evidence_node_id
evidence_recorded_at
```

这些值来自此前已通过格式校验和双重哈希的 `TaskResult` 或本地执行现场。

如果没有期望 SHA-256：

- 不得自动判定完成；
- 可以派另一个受信 Worker 独立计算实际哈希；
- 结果进入人工确认；
- 管理员确认动作必须审计。

### 14.2 Worker 实际证据

Worker 不得直接把 Master 下发的 `expected_file_name` 和 `expected_format` 原样回传。

必须从实际文件推导：

- `file_name`：`target.file_name()`；
- `format`：扩展名 + 文件魔数共同确认；
- `size_bytes`：实际元数据；
- `sha256`：实际读取计算；
- `nas_relative_path`：经过规范化的实际相对路径；
- `ingested_at`：如无法从可信元数据取得，应使用“核验时间”字段，不要伪装成入库时间。

### 14.3 Master 校验

Master 至少检查：

- 文件存在且是普通文件；
- 相对路径完全一致；
- 文件名完全一致；
- 格式完全一致；
- 大小与期望完全一致；
- SHA-256 与期望完全一致；
- SHA-256 是 64 位十六进制；
- `task_id` 与核验请求一致；
- 回报节点是被指定的核验节点；
- 任务仍处于“待确认”；
- 核验请求没有过期；
- 同一核验结果幂等。

只满足最小文件大小不能自动完成“待确认”任务。

### 14.4 核验失败

失败时不要统一放回“待处理”。按原因处理：

- 文件不存在：可重新排队；
- NAS 不可写：保持待确认并把节点置“存储异常”；
- 哈希冲突：保持待确认并产生严重告警；
- 格式或路径冲突：保持待确认；
- 证据缺失：保持待确认；
- 明确证明旧临时文件无效：清理后重新排队。

哈希冲突不能自动重下并覆盖现有文件。

## 15. 其他必须修复的问题

### 15.1 心跳续租错误不能忽略

`handle_heartbeat` 中任务续租的 SQL 结果不得使用 `let _ = ...` 忽略。

必须区分：

- 成功续租 1 行；
- 未匹配任何行；
- 数据库错误；
- 非法执行标识。

未匹配时下发停止裁决；数据库错误记录告警但不要错误地确认租约有效。

### 15.2 SSE 事件类型

```rust
OperationSource::Worker => "工作节点"
```

增加迁移：

```sql
UPDATE operation_logs SET source = '工作节点' WHERE source = 'Worker';
```

扫描所有业务字段，禁止残留：

```text
Registered
Pending
Running
Completed
Failed
Online
Offline
Available
Disabled
Worker（作为业务来源时）
```

技术字段、协议名和品牌名不在此限制内。

### 15.4 格式与静态检查

当前：

- `cargo fmt --all -- --check` 失败；

### 15.5 依赖审计

## 22. 禁止的修复捷径

以下做法一律不接受：

- 关闭 `require_client_cert` 来让 Worker 连上；
- 把伪造的证书指纹写进 Worker metadata；
- 使用 Node CA 假装已经验证 Caddy 服务端证书；
- 继续用 `exists + rename` 声称不会覆盖；
- 通过自动改名保存冲突文件并判任务成功；
- 只检查文件大小就完成 NAS 核验；
- 把 Master 下发的期望文件名原样回传当作实际证据；
- 进程重启后直接丢弃 SQLite 现场；
- 进程重启后无条件重下全部任务；
- 只保护“执行中”的共享批次；
- 只设置 `cancel_requested` 却不通知在线 Worker；
- 继续信任 JWT 中的旧角色；
- 把认证 token 保存在 localStorage；
- 对所有来源开放 CORS；
- 保留公网 CDN 作为生产依赖；
- 用固定 4096 字节读取实现 HTTP 代理；
- Webshare 同步失败时把全部代理停用；
- 数据库测试提前返回后仍统计为通过；
- 通过全局关闭 Clippy 规则让检查变绿；
- 文档先写“全部完成”，之后再补测试。

## 24. 最终完成定义

只有满足以下场景，修复才算完成：

> 在真实生产式 TLS/mTLS、真实 PostgreSQL、真实 Webshare 测试代理、真实 NAS 挂载和真实 Chromium 环境下，管理员创建批次并设置优先级后，任意可用 Worker 能通过固定出口 IP 下载正确图书；文件经过格式校验、本地哈希、NAS 临时文件哈希和不覆盖原子提交后，全局只保留一份；Master 幂等记账。下载期间发生网络断开、Worker 重启、Master 重启、批次取消、代理失效或重复上报时，不产生错误完成、重复额度、不同哈希覆盖或无法解释的执行现场。禁用管理员或 Worker 后，旧会话和旧证书不能继续操作系统。所有强制集成测试真实执行且通过。

在达到这一定义前，项目状态应标记为：


不得标记为：

```text
全部生产化修复项已落地
生产就绪
```
