## 本次实现

- 统一 API 客户端只合并同 URL 的在途 GET；参数排序后生成 URL，请求完成或失败即移除。写操作开始和结束、会话切换时清空合并表，写后的刷新不会复用写前请求。旧请求完成不会删除新请求条目。覆盖所有通过 api.get 发起的读取，独立标签页之间不共享。
- 所有已匹配 /api/ 路由的 GET（排除 SSE）添加 Server-Timing，超过 1 秒记录路由模板、耗时、状态码。无查询参数、请求体和 SQL 内容；测量至响应头生成，流式传输耗时不在其中。
- 统计缓存过期时，在创建后台任务前尝试取得刷新锁，已有刷新则直接返回旧快照，防止堆积等待任务。冷缓存从计算完成时起算有效期，继续使用已有 5 分钟 TTL。
- 总览执行中批次数改成数据库 count(*)，减少传输和反序列化，并修正原先仅取前 200 批造成的计数上限。

没有使用全局响应缓存或全局 SQL 超时，避免影响任务状态刷新与长期运行的导入事务。未增加大表索引：已有列表索引表现正常，新增索引应以具体慢查询计划为依据。

## 持久化统计与分页实现

本轮在前述公共层优化之上实现：

- 新增迁移 `0022_query_snapshots.sql`，只创建小型主键快照表，不在迁移期间运行重统计。
- 统计服务统一位于 `catalog/stats.rs`。启动和周期刷新共用一条路径；快照有效期 300 秒，后台每次完成后等待 30 秒再检查。进程内锁加 PostgreSQL 事务咨询锁防止多实例同时计算。
- HTTP `/api/catalog/stats` 只读内存或主键快照。重启可以读取上次结果；尚无快照时返回 `ready=false`。新增 `computed_at` 和 `stale`，客户端不会把未计算的占位值显示为零。
- 聚合在一个 SQL 的同一 MVCC 快照中计算，全部成功后才原子更新快照。数据库错误不再变成全零成功结果。刷新事务单独限制每条语句 120 秒，失败保留旧快照并间隔重试；不限制其他业务连接。
- 前端总览、书目概览和质量页共用统计读取 hook。首次生成/过期每 5 秒检查一次，正常每 30 秒读取一次；统计刷新不再重新请求导入记录、候选列表和执行记录。
- 总库 PostgreSQL 查询使用绑定参数动态构建条件，固定升降序并采用键集游标。先物化当前页最多 101 个 ID（100 个结果加下一页探测），再加载作品、节点和最近执行阶段。作者/标识符/文件仍采用现有批量读取。
- 出版社筛选同时接入 PostgreSQL 和 OpenSearch。关键词仍优先 OpenSearch，故障回退数据库。
- 数据库回退搜索不再额外读取全表估计行数或虚构状态/语言分面。`total_is_exact` 明确区分精确总数与已知下界，前端非精确场景只展示本页条数和是否可继续翻页。

统计快照允许分钟级延迟，任务进度继续由原有任务接口读取。本轮未批量重写其他业务列表的分页协议，也未增加生产大表索引；后续按慢接口日志和实际执行计划逐项处理。
