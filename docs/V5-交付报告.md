## 5. Worker 首次注册完整时序

```
Worker（新机器）                 Master                      管理员
    │ 生成 installation_id+私钥+CSR │                            │
    ├─ RegisterNode(nonce签名) ────►│  校验CSR/指纹/签名/限流     │
    │                               │  建节点(待审核)+注册会话    │
    │◄── node_id+会话令牌+挑战值 ────┤  （令牌只存哈希）            │
    │ 落盘待审核身份(0600)          │                            │
    ├─ WatchRegistration(每15s) ───►│  校验会话令牌+挑战签名      │
    │◄── 待审核                     │                            │
    │       ...                    │        ┌────────────────────┤
    │                               │        │ 批准(槽位+备注)     │
    │                               │  单事务: 锁行→签证书→生成    │
    │                               │  节点令牌→领用会话→已批准    │
    ├─ WatchRegistration ──────────►│  校验通过                   │
    │◄── 证书+CA+节点令牌(一次性)    │  令牌明文清空                │
    │ 校验cert/key/chain后原子落盘   │                            │
    ├─ OpenLink(mTLS+指纹+令牌) ───►│  方法级校验:证书指纹+已批准   │
    │◄── 配置下发                   │  未禁用/未吊销              │
    │ 上线                          │                            │
```

重启复用：
- 已批准+证书完整 → 直接 OpenLink；
- 待审核 → 复用本地会话继续轮询，不重复建节点；
- 已拒绝/已禁用 → 停止高频重试，显示明确原因；
- 身份部分损坏 → 明确报「身份异常」，绝不静默重建（需 `reset-identity` + 管理员处理）。

## 6. 权限与安全控制说明

| 控制点 | 实现 |
|---|---|
| 注册≠授权 | RegisterNode 只建「待审核」节点；批准前不签证书、不发令牌、无法 OpenLink |
| 方法级 mTLS | `OpenLink` 调用 `authenticate(…, require_cert=true)`：必须有证书指纹、指纹属于该节点、节点「已批准」、未禁用、证书未吊销（`fingerprint_owner` 查 revoked_at/not_after） |
| 私钥持有证明 | nonce/challenge 用 CSR 私钥签名（ring ECDSA P-256），签名错误直接拒绝 |
| 幂等与身份 | 同安装标识+同公钥不重复建节点；同安装标识+公钥突变 → 安全异常拒绝并审计 |
| 限流 | 来源 IP / 安装标识双维度固定窗口（30 次/10 分钟）；全局待审核上限 500；会话查询上限 50 次 |
| 令牌安全 | 注册会话令牌与节点令牌只存哈希；明文令牌仅批准后一次性下发（`pending_node_token` 领取即清空）；日志不输出令牌/私钥 |
| 管理员权限 | 前端矩阵（超级管理员/任务管理员/只读用户）+ 后端 `require_super_admin`/`require_write` 双重强制；只读用户点写操作看到明确「权限不足」提示 |
| CSRF | Cookie 会话 + `X-Requested-With: fetch` 头 + Origin 校验（本地联调 changeOrigin=false） |
| 名称非身份 | 0005 删除 name UNIQUE；两台同名机器可各自注册（身份是 installation_id + 指纹） |
| NAS 路径 | Master 只下发相对路径，Worker 本地拼挂载根，仍拒绝 `..`/绝对路径（V4 约束未动） |

## 9. 部署和回滚步骤

### 上线顺序（V5 12.2）

1. 备份 PostgreSQL、当前镜像标签、Caddy 与 Master 配置、在线 Worker 清单（版本/节点 ID/证书指纹）。
2. 构建并部署新 Master（含 0004/0005 迁移；0005 需先确认业务上无「同名节点合并」依赖——已删除该约束）。
3. 构建并部署新 `admin-web`（Dockerfile 已切换，web_root=/app/admin-web/dist）。
4. 小范围升级 1 台 Worker 验证直连注册（只配置 endpoint → run）。
5. 验证审批、证书、长连接、NAS、下载后分批升级其余 Worker。
6. 观察一个完整任务周期后再进入下一阶段。

### 回滚

- 前端失败：镜像切回旧前端（Vue 若已删，可回滚到上一镜像标签）；**不**回滚已创建的节点身份数据。
- 新 Worker 协议失败：兼容期内旧 `enroll --code` 仍可用，可临时回旧注册流程。
- 数据库：迁移向前兼容、不删列，回滚无需反向 SQL；`worker_nodes.name` 约束若需恢复可手工 `CREATE UNIQUE INDEX`（但会使同名机器注册失败，不建议）。

## 附：未实现项 / 已知取舍（如实说明）

1. **WatchRegistration 为单事件轮询而非真流式**：proto 声明为 `stream`，实现用 `futures::stream::once` 返回单事件；Worker 每 15 秒轮询一次。语义与流式等价（都是查询审批结果），但不符合「真推送」字面；Worker 侧已是轮询退避，无重复建节点风险。如需真推送需心跳通道复用，留待后续。
2. **Caddy 指纹头透传**：本地无 Caddy 无法真实验证 `{http.request.tls.client.fingerprint}` 头注入；Worker insecure 联调由 Worker 自报指纹（Master 仍校验归属）。
3. **阶段 7 未执行**（有意）：见第 8 节，兼容期保留旧注册码机制。
4. **前端 i18n**：全部中文硬编码，无 i18n 框架（方案要求中文展示，未要求多语言）。
