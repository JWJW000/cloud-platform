# 已有图书馆藏扫描与统一“已下载”状态实施方案 V1

> 日期：2026-08-25
> 适用目录：`cloud-platform/`
> 目标数据位置：`/Volumes/PortableSSD/202608 (1)` 及后续客户端/NAS 下载目录
> 文档性质：可直接实施的数据库、Master、Worker、前端、迁移与验收方案

## 1. 目标与统一语义

本方案解决两个连续问题：

1. 将现有书单增量导入云端图书总库；
2. 将客户端、移动硬盘或 NAS 上已经存在的图书文件登记为有效馆藏，使其对应图书自动变为“已下载”。

系统不建立“客户端下载”和“云端下载”两套业务分类。所有文件均进入同一馆藏体系，前端只展示以下业务事实：

- 已下载；
- 待下载；
- 下载中；
- 待确认；
- 暂时失败；
- 文件离线或丢失。

“云端下载”在本系统中的准确含义是“由云端统一调度的分布式下载”。图书文件仍直接保存在 Worker 所在机器、移动硬盘或 NAS，不经过云服务器中转。客户端历史文件和客户端下载完成文件只允许在内部审计证据中记录发现方式，不作为前端标签、筛选条件或独立任务类型。

## 2. 当前能力与缺口

### 2.1 当前已经具备

1. 总库书目导入、来源记录、规范作品、版本和来源资产表；
2. `library_files`、`holdings` 和 `acquisition_targets` 馆藏及获取状态模型；
3. 单文件馆藏提交接口 `/api/catalog/storage/commit`；
4. Worker 下载完成后提交路径、格式、大小和哈希证据的闭环；
5. 同一 SHA-256 文件幂等、版本馆藏关联和“已下载”状态推进；
6. 小型 CSV/TSV/TXT 网页导入和只读服务器 manifest 导入。

### 2.2 当前缺口

1. 没有在 Worker 上只读扫描已有目录的馆藏扫描器；
2. 没有面向数十万或数百万文件的分批上报、确认和断点续扫协议；
3. 没有将历史文件自动匹配到 `edition_id` 的统一匹配模块；
4. 没有“匹配不确定”队列和人工确认页面；
5. `library_files` 当前把内容实体与物理位置放在同一行，不能准确表示同一文件在多个磁盘/NAS 上有副本；
6. 网页导入适合小型补充书单，不适合约 4.2 GB、约 1,900 万来源记录的首次全量导入；
7. 当前无法仅凭书单中的 MD5 或格式判断文件确实存在，因此不能把“已出现在书单”直接当作“已下载”。

## 3. 最终业务流程

```text
书目文件
  → 书目预检
  → 规范化、去重、消歧
  → works / editions / source_assets
  → 生成或更新全局 acquisition_targets

本地磁盘 / NAS 已有文件
  → Worker 只读扫描
  → 格式、大小、SHA-256/MD5 文件证据
  → 云端统一匹配模块
      ├─ 唯一确定匹配 → library file + location + holding
      ├─ 多候选/低置信度 → 待确认
      └─ 暂无书目 → 未匹配池，后续书目导入后自动重试
  → 有有效可访问馆藏 → acquisition_target = 已下载
  → 无有效馆藏 → 保留在同一个全局待下载池

未来 Worker 新下载文件
  → 使用同一个馆藏提交模块
  → 与历史扫描文件产生完全相同的“已下载”结果
```

首次迁移必须先导入书目，再扫描已有文件。顺序反过来时，文件可以进入未匹配池，但会增加大量后续重匹配工作。

## 4. 核心模块设计

### 4.1 馆藏登记深模块

新增 `catalog::inventory` 模块，在以下 seam 提供一个小 interface：

```rust
pub async fn ingest_inventory_batch(
    db: &PgPool,
    batch: InventoryEvidenceBatch,
) -> Result<InventoryBatchOutcome>;
```

调用者只需要提交已验证的批次证据。该模块内部统一完成：

1. 输入边界校验；
2. 扫描任务幂等；
3. 内容哈希去重；
4. 书目候选召回；
5. 匹配评分与冲突裁决；
6. 文件内容实体及物理位置登记；
7. `holdings` 建立；
8. 获取目标状态重算；
9. 待确认记录创建；
10. 搜索 Outbox 与审计写入。

网页处理器、gRPC 处理器、历史文件扫描和未来下载完成上报都不能自行拼接 SQL 或分别实现匹配规则。删除该模块时，上述复杂性会重新散落到多个调用者，说明该模块具有足够深度。

### 4.2 扫描模块

在 `worker-agent` 新增 `inventory` 模块：

```rust
pub async fn scan_inventory(
    roots: &ConfiguredLibraryRoots,
    assignment: InventoryScanAssignment,
    sink: &dyn InventoryBatchSink,
    cancel: CancellationToken,
) -> Result<InventoryScanSummary>;
```

模块隐藏目录遍历、格式识别、哈希缓存、并发限制、批量上报、断点和取消逻辑。生产使用 gRPC sink adapter，测试使用内存 sink adapter。云端任务只能引用本地预配置的 `root_id`，不能提供绝对路径。

### 4.3 匹配模块

新增 `catalog::inventory_matcher` 内部 seam，输入一个文件证据，输出以下封闭结果之一：

```rust
enum InventoryMatchDecision {
    Matched { edition_id: Uuid, method: MatchMethod, score: u16 },
    NeedsReview { candidates: Vec<MatchCandidate>, reason: String },
    Unmatched { reason: String },
}
```

该 seam 是馆藏登记模块的内部 seam，不直接暴露给 HTTP 或 Worker。测试通过馆藏登记模块 interface 验证最终数据库结果，不依赖内部 SQL 或评分实现。

## 5. 数据库设计

新增迁移建议命名：

```text
crates/master-server/migrations/0010_inventory_scan_and_file_locations.sql
```

### 5.1 存储位置

```sql
CREATE TABLE storage_locations (
    id                  UUID PRIMARY KEY,
    node_id             UUID REFERENCES worker_nodes(id) ON DELETE SET NULL,
    root_key            TEXT NOT NULL,
    backend             TEXT NOT NULL CHECK (backend IN ('Local', 'NAS', 'S3', 'OSS')),
    display_name        TEXT NOT NULL,
    availability        TEXT NOT NULL DEFAULT '未知'
                        CHECK (availability IN ('在线', '离线', '未知', '已停用')),
    last_seen_at        TIMESTAMPTZ,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (node_id, root_key)
);
```

`root_key` 是 Worker 本地配置中的稳定别名，例如 `portable_202608`，不是绝对路径。云端不保存 `/Volumes/...` 绝对路径，避免泄露本地目录结构并防止服务端控制任意目录。

### 5.2 文件物理副本

保留 `library_files` 作为内容实体，继续以 SHA-256 唯一。新增物理位置表：

```sql
CREATE TABLE library_file_locations (
    id                  UUID PRIMARY KEY,
    library_file_id     UUID NOT NULL REFERENCES library_files(id) ON DELETE CASCADE,
    storage_location_id UUID NOT NULL REFERENCES storage_locations(id) ON DELETE CASCADE,
    object_key          TEXT NOT NULL,
    actual_size_bytes   BIGINT NOT NULL,
    verify_status       TEXT NOT NULL DEFAULT '待校验'
                        CHECK (verify_status IN ('待校验', '有效', '损坏', '丢失', '离线')),
    verified_at         TIMESTAMPTZ,
    last_seen_at        TIMESTAMPTZ NOT NULL DEFAULT now(),
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (storage_location_id, object_key)
);
```

同一 SHA-256 可以有多个物理副本。`holdings` 仍关联内容实体；“已下载”要求至少存在一个满足策略且位置状态为“有效”的副本。

迁移时将现有 `library_files.storage_backend + object_key` 回填为一个 `legacy` 存储位置和对应位置记录。完成双读、对账后，原字段保留一个版本作为兼容只读字段，下一大版本再删除。

### 5.3 扫描任务与检查点

```sql
CREATE TABLE inventory_scan_jobs (
    id                  UUID PRIMARY KEY,
    node_id             UUID NOT NULL REFERENCES worker_nodes(id),
    storage_location_id UUID NOT NULL REFERENCES storage_locations(id),
    status              TEXT NOT NULL,
    scan_mode           TEXT NOT NULL CHECK (scan_mode IN ('增量', '全量复核')),
    checkpoint          JSONB NOT NULL DEFAULT '{}'::jsonb,
    discovered_count    BIGINT NOT NULL DEFAULT 0,
    hashed_count        BIGINT NOT NULL DEFAULT 0,
    matched_count       BIGINT NOT NULL DEFAULT 0,
    review_count        BIGINT NOT NULL DEFAULT 0,
    unmatched_count     BIGINT NOT NULL DEFAULT 0,
    skipped_count       BIGINT NOT NULL DEFAULT 0,
    error_count         BIGINT NOT NULL DEFAULT 0,
    started_at          TIMESTAMPTZ,
    finished_at         TIMESTAMPTZ,
    last_error          TEXT,
    created_by          UUID REFERENCES admin_users(id),
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

状态固定为：`待下发 / 扫描中 / 暂停 / 已完成 / 部分失败 / 已取消 / 失败`。

### 5.4 扫描文件暂存与待确认

```sql
CREATE TABLE inventory_scan_entries (
    id                  UUID PRIMARY KEY,
    scan_job_id         UUID NOT NULL REFERENCES inventory_scan_jobs(id) ON DELETE CASCADE,
    storage_location_id UUID NOT NULL REFERENCES storage_locations(id),
    object_key          TEXT NOT NULL,
    file_name           TEXT NOT NULL,
    extension           TEXT NOT NULL,
    actual_size_bytes   BIGINT NOT NULL,
    modified_at         TIMESTAMPTZ,
    sha256              TEXT NOT NULL,
    md5                 TEXT,
    embedded_metadata   JSONB NOT NULL DEFAULT '{}'::jsonb,
    resolution_status   TEXT NOT NULL,
    matched_edition_id  UUID REFERENCES editions(id),
    match_method        TEXT,
    match_score         INT,
    error_reason        TEXT,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (scan_job_id, object_key)
);
```

`resolution_status` 固定为：`待处理 / 已匹配 / 待确认 / 未匹配 / 已忽略 / 失败`。

待确认候选放入单独的 `inventory_match_candidates`，保存候选 `edition_id`、命中依据和评分。管理员确认后调用同一个馆藏登记模块，不直接更新状态字段。

### 5.5 获取状态重算

将“已下载”从一次性写值改为可重算事实：

```text
edition 至少有一个 meets_strategy=true 的 holding
  且 holding 指向的 library_file 至少有一个有效在线 location
  → acquisition_target.status = 已下载

曾经有馆藏但所有 location 均离线
  → 页面显示“文件离线”
  → 不立即重新下载，等待宽限期或管理员策略

文件确认丢失/损坏且无其他有效副本
  → acquisition_target.status = 待下载 或 人工确认
```

状态重算必须集中在 `recompute_acquisition_state(edition_id)`，馆藏提交、位置离线、人工确认和复核扫描均调用这一处。

## 6. Worker 本地配置

在 `worker.toml` 增加：

```toml
[inventory]
enabled = true
hash_concurrency = 2
batch_size = 200
max_file_size_bytes = 2147483648
follow_symlinks = false

[[inventory.roots]]
id = "portable_202608"
path = "/Volumes/PortableSSD/202608 (1)"
backend = "Local"
display_name = "PortableSSD 202608"
read_only = true
```

Windows 对应示例：

```toml
[[inventory.roots]]
id = "library_nas"
path = "Z:\\Books"
backend = "NAS"
display_name = "图书 NAS"
read_only = true
```

约束：

1. `id` 在单个 Worker 内唯一且修改需人工编辑本地配置；
2. Master 只下发 `id`，Worker 本地解析真实路径；
3. 路径必须在启动时 canonicalize，并验证实际存在；
4. 默认不跟随符号链接、不扫描隐藏目录和系统目录；
5. 扫描器不移动、不重命名、不删除、不解压、不写入原目录；
6. 哈希缓存写入 Worker 自己的数据目录，不写入图书目录；
7. 根目录卸载后立即上报“离线”，不能把文件误报为丢失。

## 7. 扫描与哈希策略

### 7.1 支持格式

首版允许：

```text
epub, pdf, mobi, azw3, djvu, txt, fb2, cbz, cbr
```

压缩包默认只登记为“待确认”，不自动解压。可执行文件、脚本、设备文件、socket 和不在允许列表内的格式直接跳过并计数。

### 7.2 两阶段扫描

第一阶段快速发现：

- 相对路径；
- 文件名和扩展名；
- 大小；
- 修改时间；
- 文件系统稳定标识（平台可用时）。

第二阶段证据计算：

- 首次发现或大小/修改时间变化时计算 SHA-256；
- 只有来源书目需要 MD5 匹配时才计算 MD5，或在同一次流读取中同时计算；
- 相同相对路径、大小、修改时间且缓存证据仍有效时复用哈希；
- 哈希读取失败只影响单文件，不终止整个任务；
- 默认 2 个并发哈希任务，避免移动硬盘随机读取过载。

### 7.3 断点与幂等

1. 每 200 个文件或 30 秒上报一次批次；
2. Master 返回已持久化的批次序号作为 ACK；
3. Worker 只在收到 ACK 后推进本地检查点；
4. 断线重发通过 `(scan_job_id, object_key)` 唯一键幂等；
5. 同一文件内容通过 SHA-256 命中同一 `library_file`；
6. 同一路径内容变化时更新 location 指向的新内容实体，同时重算旧实体相关版本状态；
7. “全量复核”结束后才把本轮未见到的旧位置标为丢失，增量扫描不得执行缺失裁决。

## 8. 匹配规则与风险控制

匹配按以下顺序执行，命中唯一确定结果后停止：

1. SHA-256 已存在：直接复用内容实体及其已有版本关联；
2. MD5 唯一命中一个 `source_asset`，且大小/格式一致：自动匹配；
3. ISBN/DOI/外部编号唯一命中一个版本：自动匹配；
4. 电子书内嵌元数据中的规范书名、作者、出版社、年份组合唯一命中：自动匹配；
5. 文件名解析出的书名、作者和格式高置信度唯一命中：自动匹配；
6. 多候选、字段冲突或低置信度：进入待确认；
7. 无候选：进入未匹配池。

禁止以下行为：

- 仅因文件名部分相似就自动标记已下载；
- 用文件所在目录名直接覆盖书目字段；
- 多候选时选择搜索排序第一项；
- 将同一作品的任意格式默认关联到所有版本；
- 未校验文件可访问和哈希就写“已下载”。

自动匹配建议阈值为 900/1000；700～899 进入待确认；低于 700 为未匹配。阈值和规则版本写入扫描记录，后续调整规则时可以重跑未匹配数据。

## 9. Master 与 Worker 协议

在 `worker.proto` 新增消息，继续复用现有 mTLS `OpenLink`，不建立第二条长连接：

```text
Master → Worker
  AssignInventoryScan
  CancelInventoryScan

Worker → Master
  InventoryRootStatus
  InventoryScanStarted
  InventoryEvidenceBatch
  InventoryScanProgress
  InventoryScanFinished

Master → Worker
  InventoryBatchAck
```

`AssignInventoryScan` 只包含：

- `scan_job_id`；
- `root_id`；
- `scan_mode`；
- 允许格式；
- 批量大小；
- 检查点；
- 租约到期时间。

不得包含本地绝对路径、任意 glob、shell 命令或服务端提供的排除路径表达式。

`InventoryEvidenceBatch` 只上传元数据和哈希，绝不上传图书字节。单批限制 200 条和 1 MiB；每个路径限制 1,024 字节；内嵌元数据限制 16 KiB；服务端对条数、字符串、枚举和哈希格式再次校验。

权限要求：

- Worker 批次上报只走 mTLS gRPC，不开放匿名 HTTP；
- 所有人工确认写审计日志，记录管理员、候选、最终选择、匹配依据和时间，不记录本地绝对路径。

现有 `/api/catalog/storage/commit` 改为调用馆藏登记深模块；保留一个兼容版本后，再限制为内部使用。

## 11. 前端方案

### 11.1 数据导入页面

保留“数据导入”用于书目，不把文件目录扫描混入同一表单。页面明确提示：

> 导入书单只建立书目和待下载目标，不代表文件已经存在。已有文件请前往“馆藏扫描”。

书目导入支持：

- 小型 CSV/TSV/TXT 浏览器上传；
- 服务器已登记 manifest；
- 大库导入器运行记录只读展示；
- 重复文件哈希、成功、重复、隔离和检查点统计。

### 11.2 新增“馆藏扫描”页面

入口放在“数据与质量”导航组，页面包含：

1. 在线 Worker 及其本地登记的存储根；
2. 新建扫描：选择 Worker、根目录别名、增量/全量复核；
3. 实时阶段：发现、哈希、上报、匹配、完成；
4. 进度统计：发现、已哈希、已匹配、待确认、未匹配、跳过、失败；
5. 最近检查点、速度、预计剩余时间和错误摘要；
6. 暂停、恢复和取消；
7. 任务完成后的对账报告。

前端不展示 Worker 本地绝对路径，只展示 `display_name` 和 `root_id`。

### 11.3 待确认页面

每项展示：

- 文件名、格式、大小和哈希短值；
- 解析出的书名/作者/ISBN；
- 最多 5 个候选版本；
- 每个候选的命中字段和冲突字段；
- 选择候选、标记忽略、保持未匹配；
- 确认前影响预览：“将新增哪个馆藏、哪个获取目标会变为已下载”。

### 11.4 总库与详情页

总库仍只显示“已下载”，不增加“客户端下载”标签。详情页展示：

- 已满足的版本和格式；
- 有效副本数量；
- 存储位置显示名；
- 最近校验时间；
- 在线、离线、损坏或丢失状态。

内部扫描方式不作为普通用户可见字段。

## 12. 大书单导入器

对于 `/Volumes/PortableSSD/202608 (1)` 中约 4.2 GB、约 1,900 万来源记录的数据，新增独立命令：

```text
catalog-importer preview --root <只读目录> --source cn
catalog-importer run --root <只读目录> --source cn --resume
catalog-importer status <run-id>
```

导入器在能读取移动硬盘的机器运行，调用 Master 的受控批量导入协议，只上传书目行，不上传图书文件。实现要求：

1. XLSX/CSV/TSV 流式读取；
2. 单批 5,000～25,000 行，压缩传输；
3. 文件、工作表、行号和 SHA-256 检查点；
4. 同一文件重复运行幂等；
5. 原始文件全程只读；
6. 服务端行数、单字段长度和批次大小均有上限；
7. 失败批次可重传，不回滚已确认批次；
8. 最终满足“总行数 = 成功 + 重复 + 隔离”。

网页仍用于小型增量书单，不承担首次大库上传。

## 13. 安全与滥用场景

### 13.1 信任边界

1. 本地文件名、电子书元数据和书单内容均是不可信输入；
2. Worker 上报数据必须经过 gRPC 消息大小、字段长度、枚举和哈希格式校验；
3. Master 下发任务不能获得任意文件系统访问权；
4. 管理员人工确认是高权限写操作；
5. 图书文件本身不得进入云端日志、数据库或消息队列。

### 13.2 必须覆盖的滥用测试

- 路径包含 `../`、绝对路径、NUL 或超长字符；
- 符号链接逃出根目录；
- 目录循环和百万级小文件导致资源耗尽；
- 文件扫描期间被替换，哈希前后元数据不一致；
- 伪造 SHA-256/MD5、错误大小或非法格式；
- 同一批次无限重放；
- 未授权管理员创建或确认扫描；
- Worker 尝试冒充其他节点的存储位置；
- 电子书元数据包含 HTML/脚本；
- 压缩炸弹或恶意归档；
- 移动硬盘卸载被误判为全部文件丢失；
- 多候选被错误自动归入第一项。

### 13.3 控制措施

- canonicalize 后验证路径仍位于本地白名单根目录；
- 默认禁止跟随符号链接；
- 只读打开文件，不请求写权限；
- 哈希前后比较大小和修改时间，变化则重试或待确认；
- 严格格式允许列表和魔数检查，不信任扩展名；
- 每节点限一个全量扫描、有限哈希并发和可取消任务；
- 批次和总任务速率限制；
- React 默认转义文件名和元数据，禁止 `innerHTML`；
- SQL 全部参数化；
- 管理操作审计；
- 扫描任务租约和节点身份绑定；
- 全量复核完成前不得批量标记丢失；
- 绝对路径仅存在 Worker 本地配置，不上传、不记录日志。

## 17. 验收标准

必须同时满足：

1. 书目导入不上传图书文件；
2. 扫描器不修改 `/Volumes/PortableSSD/202608 (1)` 中任何文件；
3. 客户端历史文件和新下载文件使用同一馆藏登记模块；
4. 前端没有“客户端下载/云端下载”分类；
5. 每条“已下载”均能下钻到有效文件内容、至少一个有效位置、大小和 SHA-256；
6. 同一文件重复扫描不会增加 `library_files`；
7. 同一文件位于多个位置时保存多个副本，不重复保存内容实体；
8. 多候选不自动误匹配；
9. 断网重传、Worker 重启和 Master 重启不重复入库；
10. 磁盘离线不会立即把全部文件判为丢失；
11. 全量复核能识别真实丢失文件并重算获取状态；
12. 新书单导入后，未匹配文件自动重新匹配；
13. 所有未满足图书仍进入同一个全局下载池；
14. 迁移报告满足来源行、文件、匹配、待确认、未匹配和隔离数量闭合；
15. CI、Clippy、数据库集成、三平台 Worker、前端和生产镜像门禁全部通过。

## 18. 实施后的实际操作步骤

### 18.1 首次配置

在连接移动硬盘的客户端 `worker.toml` 登记：

```toml
[[inventory.roots]]
id = "portable_202608"
path = "/Volumes/PortableSSD/202608 (1)"
backend = "Local"
display_name = "PortableSSD 202608"
read_only = true
```

重启 Worker，管理后台应只看到“PortableSSD 202608 / portable_202608 / 在线”，看不到绝对路径。

### 18.2 导入书目

1. 小型补充书单：管理后台 → 数据导入 → 新建数据导入；
2. 大型书单：在移动硬盘所在机器运行 `catalog-importer preview`；
3. 核对样本字段和总行数；
4. 执行 `catalog-importer run --resume`；
5. 处理隔离行并完成总行数对账。

### 18.3 扫描已有文件

1. 管理后台 → 馆藏扫描 → 新建扫描；
2. 选择已连接的 Worker；
3. 选择“PortableSSD 202608”；
4. 首次选择“增量扫描”；
5. 观察发现、哈希、匹配和上报进度；
6. 完成后处理待确认；
7. 未匹配文件保留，后续补充书目后自动重试；
8. 对账无误后执行一次“全量复核”。

### 18.4 后续运行

- 客户端新下载完成后自动入统一馆藏，不需要额外操作；
- 新增书单自动汇入同一个总库和待下载池；
- 日常只运行增量扫描；
- 定期运行全量复核检查丢失、损坏和离线副本；
- 页面始终统一显示“已下载”，不区分发现来源。

## 19. 不在本方案中执行的事项

1. 不把图书文件批量上传到云服务器；
2. 不自动移动、重命名或整理现有文件；
3. 不自动解压 RAR/ZIP；
4. 不因书单记录存在就直接标记已下载；
5. 不在服务端保存 Worker 的本地绝对路径；
6. 不删除无法匹配的文件；
7. 不在 DNS、Worker 正式域名未完成前扩大生产 Worker 发布范围。

## 20. 最终结论

正确实现不是给客户端文件增加一个“客户端下载”标签，而是让所有文件都通过统一馆藏证据闭环：

```text
有效文件 + 可访问位置 + 大小 + SHA-256 + 明确版本关联
  = 已下载
```

书目导入负责回答“图书馆应该有哪些书”，馆藏扫描负责回答“哪些书已经有有效文件”，全局获取任务只下载两者差集。这样已有文件、未来客户端下载和云端调度下载最终都收敛到同一套事实库、同一套状态和同一个持续运行的分布式下载任务。
